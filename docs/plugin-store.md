# 插件商店首版

商店现已并入内置插件 `system.plugin-manager`（插件中心），提供目录、搜索、详情、安装与手动更新。搜索「插件中心」「插件管理」或「插件商店」均进入同一插件；默认显示「已安装」，通过「发现」浏览目录。沿用主窗口页头、返回与拆出操作，插件中心不可禁用或卸载。

## 本地使用

`make dev` 准备应用检索（仅 macOS）、设置、插件中心三个内置插件。插件中心默认显示本地插件，进入「发现」后才请求目录；网络异常不影响返回「已安装」进行管理。本地目录和 ZIP 安装位于顶部「本地安装」，创建插件与数据清理位于「更多」。目录采用紧凑卡片，默认显示图标、名称、单行简介及来源 / 版本，安装按钮与元信息同行；完整插件 ID、仓库地址和版本选择放在详情页。

已有日常实例使用新版宿主后，启动时自动迁移旧管理包与商店包；先升级插件中心，再移除旧商店安装包。识别依据是发行快照的扁平形态（只有 `manifest.json` 与 `icon.svg`，声明为中心 / 商店形态）与既有 0.6.0 已知指纹，不再要求每次发行登记新指纹，因此跨版本与跨平台升级均可迁移。带额外文件、子目录、链接、开发安装或本地修改的包保留并提示手动处理，可从恢复入口升级本仓库的 `plugins/system-plugin-manager`；发行版用户也可删除 `%APPDATA%\Sinan\plugins\system.plugin-manager` 后重启，由宿主重装内置版本。迁移保留配置、私有数据、使用记录和目录缓存；不会将空插件目录自动填充为完整系统安装。详见 [ADR 0048](adr/0048-unified-plugin-center.md) 与 [ADR 0069](adr/0069-flat-snapshot-migration.md)。只复制 manifest 不会增加旧宿主中不存在的可信组件。

JSON 工具 0.4.1 已发布并登记，提供 macOS arm64、amd64 安装包；它使用相同的纯前端资源，不含原生后端。可在商店刷新后安装或显式更新。未发布插件仍显示“待发布”，不会用源码版本号生成伪安装包，也不会将本地源码目录当作已发布版本。

## 目录与发行契约

首版目录固定为 `zhyipeng/sinan-plugin-registry`，分支 `main`。商店使用公开 GitHub API 获取目录树，随后按树中固定 blob SHA 读取 `plugins/<plugin-id>/plugin.json`。`submissions`、任意外部索引和用户指定 URL 不作为安装来源。不调用 gh、不读取本机 GitHub 凭据。

目录资料字段为 schemaVersion（1）、id、name、summary、publisher.kind（official/community）、source（repository/path）、status 和 releases。状态支持 pending-release、published、withdrawn。仅 published 中的正式版本允许安装，pending-release 必须无版本。

正式版本记录包含：

| 字段 | 约束 |
| --- | --- |
| schemaVersion、pluginId、name | 记录版本 1，插件 ID 与资料一致，包名称与该发布记录一致 |
| version、minHostVersion | 三段数值版本；当前宿主版本 0.1.0；不支持预发布标签 |
| repository、tag、commit、releaseId | owner/repo，`<plugin-id>-v<version>`（兼容旧 `v<version>`），40 位源码提交摘要，正整数 Release ID |
| compatibility | apiVersion 为 1；uiBridgeVersion 为 1 或 2 |
| assets | 当前 OS/架构匹配的发行资产，至少一个、最多八个 |

每项资产包含 os（darwin/linux/windows）、arch（arm64/amd64）、file、sha256、size、assetId、downloadUrl。文件名为 `<id>-<version>-<os>-<arch>.zip`，URL 必须对应记录中的仓库、tag 和文件名，源码地址也须与发行仓库一致。实际下载使用固定 Asset ID 的公开 API；摘要、大小必须匹配。

目录仓库的校验器支持相同字段。模板 submissions 可继续沿用旧字段，审核者纳入正式 releases 时补齐 minHostVersion。维护者应核查真实资产与源码，不应仅凭脚本校验合格就发布。版本记录中的 commit、Release ID 是审核资料；宿主不会据此证明二进制可复现或自动完成源码审核。

## 安装与更新

1. 本地搜索已载入的名称、ID 与摘要。在目录卡片直接点击「安装」或「更新」，默认选择当前平台与宿主兼容的最新版本；无需进入详情；校验通过后直接安装，不再要求二次确认。已安装且无可用新版本时显示「已安装」。需要手动选择其他版本时进入插件详情。
2. 卡片及详情中的「安装 / 更新」均强制核验最新目录。目录修订变化时要求刷新，离线缓存不能安装。
3. 下载并验证归档，受限解压至私有缓存；复用内核包预览，核对 ID、名称和版本。
4. 所有插件（包括原生插件）校验通过后立即应用；点击安装或更新即授权本次原生候选运行，不再要求额外确认。应用前仍再次读取最新目录，拒绝已撤回或替换的资产，然后用包指纹和已安装包指纹应用。
5. 更新保留既有配置、数据与启用状态；运行中视图按现有升级机制撤销。失败回退复用内核行为。

本地目录 / ZIP 同样点击「安装 / 更新」后自动检查和应用，包括原生包均不再要求二次确认；检查与应用仍分别核验包指纹，拒绝中途替换的文件。已有相同内容时只显示提示，不重复安装。

在主输入框键入或粘贴符合发行命名规则的 ZIP 绝对路径，插件中心会提供「安装插件」结果。选中结果会打开本地安装并开始检查，完成后在插件中心显示结果。普通文件名的 ZIP 可继续通过「本地安装」选择。

这是显式选择版本的手动更新，也允许在详情选择旧版本后直接应用。没有自动更新或根据相同 ID 自动授予信任。开发链接、本地包已变更及受保护插件不能被商店覆盖。目录下架仅阻止后续安装，不自动卸载或停用本地插件。

## 资源和信任边界

目录缓存位于 `os.UserCacheDir()/Sinan/plugin-store`，正常读取五分钟内复用缓存，手动刷新使用条件请求。联网失败且已有缓存时可继续浏览，界面标明缓存状态。GitHub 限流时显示错误并保留已有资料。

目录最多 128 项，每份资料最多 128 KiB、合计最多 2 MiB；版本最多 64 个。包下载及解压内容各限 64 MiB、最多 2048 个 ZIP 条目，拒绝路径越界、符号链接、特殊文件和重复路径。下载仅允许 GitHub 及固定发行资产域名的 HTTPS 重定向。临时预览十分钟有效、单次使用，每服务最多四个待处理操作；取消、失效后的下一次清理与正常退出会释放暂存目录。进程被强制终止可能遗留缓存，未实现跨进程自动清扫。

首版实现 GitHub HTTPS、固定目录审核、资产 SHA-256 与本地指纹检查，尚无独立目录签名、签名密钥轮换及完整撤销体系。哈希不能替代作者签名，原生进程以用户权限运行，不能宣称操作系统沙箱。架构基线中面向公共第三方分发的完整签名及治理要求仍待完成。

验证采用无界面的 HTTP/ZIP 夹具、真实内核安装与更新测试，以及构建和竞态检查。日常验证不启动真实桌面或浏览器，不据此声明焦点、输入法和视觉体验已人工验收。

### 目录图标

`plugins/<id>/plugin.json` 支持可选 `icon`，内容为 SVG、PNG 或 JPEG 的 base64 图片 data URL。图标最多 64 KiB，位图宽高各最多 1024 像素；SVG 使用静态基础形状，不含脚本、样式、外部引用及实体。该字段随目录快照缓存，不请求额外远程图片。未提供时可使用已安装插件图标，否则显示插件名首字。新增字段需要支持图标的新版宿主，参见 ADR 0046。

## GitHub 加速（可选）

商店的目录读取与插件包下载默认直连官方 GitHub，可选启用镜像加速以缓解访问受限或限流。配置位于系统「设置」页的「插件中心」分组，含两项：

- **GitHub 加速服务**（`select`）：`自动`（默认，官方优先、失败逐个回退内置镜像）、`仅官方，不加速`、指定内置镜像（`github.chenc.dev`、`gh-proxy.com`）或 `自定义模板`。
- **自定义加速模板**（`text`）：模板中 `{url}` 代表原始完整地址，例如 `https://example.com/{url}`。只能使用 `https`，且必须包含 `{url}`，否则该模板被忽略并回退官方。

首版内置服务仅收录实测能代理 `api.github.com` 的两项：`github.chenc.dev`（`https://github.chenc.dev/{url}`）与 `gh-proxy.com`（`https://gh-proxy.com/{url}`）。内置清单是尽力而为，可用性不保证，失败一律回退官方。

行为与边界：

- 目录请求的候选顺序按设置解析：`自动` 为官方后接内置镜像；指定镜像或自定义模板时先走所选目标，再回退官方与其余内置；`仅官方` 只请求官方。目录读取与发行资产下载共用同一套候选与模板规则。
- 同一请求依次尝试候选，任一返回 200/304 即采用；全部失败时按主因归类为「GitHub 请求受限」「插件目录暂不可用」或「无法连接」。已有缓存时仍回退显示缓存并提示。
- 为兼容镜像的规范化跳转（如 `github.chenc.dev` 将 `https://` 规范化为 `/https:/`），允许与首个请求同主机的 HTTPS 重定向；跨主机重定向继续拒绝。下载重定向仍只允许已批准的 GitHub 资产域名或同主机。
- 镜像只改变请求出口，不改变目录内容校验、资产 SHA-256、大小、ZIP 解压限制、指纹与信任流程。不读取任何本机 GitHub 凭据。见 [ADR 0052](adr/0052-github-mirror-acceleration.md)。

## 插件独立发布标签

不同插件可在同一源码仓库使用相同版本号。新发布使用 `<plugin-id>-v<version>`，例如 `tools.calendar-v0.1.0` 和 `tools.clipboard-v0.1.0`；标签中的 ID、版本必须与发布记录严格一致。既有 `v<version>` 继续接受，同一插件仍禁止重复版本，文件名和资产校验规则不变。桌面应用自身的 `v<version>` 发布标签不受影响。

这是目录标签约束的兼容扩展，不增加 JSON 字段、权限、SDK 或桥版本；旧宿主会拒绝新格式记录，且可能回退整个目录快照。应先更新宿主，再使用新格式登记发行。现有已发布记录与资产不改写、不降级，未来新增版本无需为其他插件跳号。见 [ADR 0065](adr/0065-independent-plugin-release-tags.md)。

## 后台下载安装任务

点击安装或更新会立即提交宿主侧任务，下载、校验和应用不依赖商店页面存活；可切换页面、隐藏窗口或拆出插件中心。插件中心在「发现」之后新增独立「下载安装」Tab，展示任务状态，重新进入仍可查看。下载阶段可取消，进入安装应用阶段后需等待完成；失败或取消可重试，重试重新核验最新目录。

最多四个活动任务，同一插件不重复下载，最近最多保留 32 条任务记录。任务具有十分钟预算，单个插件包下载候选最多五分钟，仍受任务剩余时间约束。超时、传输中断与下载后的大小或 SHA-256 不匹配分别提示。下载进度条按已写入缓存的实际字节与目录登记的归档大小计算，展示大小和百分比。目录准备阶段使用不定进度，下载完成后分别显示校验和安装状态。镜像重试从零重新计数，下载 100% 不代表安装完成。退出应用取消网络工作并等待安装收尾，重启后不恢复任务或断点续传。见 [ADR 0072](adr/0072-background-plugin-installation.md)。
