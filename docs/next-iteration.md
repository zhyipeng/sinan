# 下一轮开发计划

日期：2026-11-04。状态：本轮核心实现与原型验证已完成。基线：Phase 1 运行原型、聚焦式 Shell 和图标接入已提交。

## 目标

完成多 Provider 搜索和插件 UI 隔离两个技术验证，为下一阶段的应用检索系统插件建立接口与运行边界。遵循[架构指导方案](architecture.md)中“先验证机制，再扩展业务”的顺序。

## 启动本轮时的基础与缺口

已具备：动态安装与卸载、声明式和可信原生进程插件、stdio RPC、命令执行、全局热键、托盘、动态窗口高度及 macOS 多屏定位。

尚待解决：

- Shell 目前只在前端过滤已声明命令，没有 Search Coordinator、动态 Provider 或统一搜索结果模型。
- `Manager.Execute` 在整个调用期间持有全局互斥锁，不支持不同插件并行执行；运行时取消通过终止整个进程实现。
- 尚无独立的插件 UI 承载与受限消息桥。当前 Wails 服务只应提供给可信 Shell。
- 三屏、全屏应用、热键、输入法与托盘仍需实机回归。现有测试通过不能替代这些检查。

## 实施顺序

### 1. 确认桌面交互基线

检查当前构建在内置 Retina、DELL P2723D、DELL U2719D 上的行为：

- 鼠标所在屏幕呼出，水平居中，顶部位于原生可用区域高度的 20%。
- Command + Space 显示 / 隐藏，空查询高 50 DIP，输入后伸缩时顶部保持固定。
- 全屏应用上可输入、不切换 Space；切换应用和 Escape 正常隐藏。
- 中文组词回车不误执行；托盘可找回窗口并退出。

验收：记录屏幕布局、系统版本和实测结果；有失败先修复对应交互，再接新的搜索流程。

### 2. 建立搜索契约与协调器

交付范围：

- Manifest 增加搜索贡献声明、触发条件与按需激活支持，保持现有命令插件可用。
- 在 `packages/plugin-protocol`、`schemas/` 和 SDK 中统一查询、结果、执行动作及能力协商契约。
- 在 `internal/search/` 建立 Search Coordinator，统一静态命令索引和动态 Provider 的结果；Shell 只负责输入、列表和选择。
- 第一版按 Provider 返回完整结果批次，宿主在每个 Provider 完成时增量展示，暂不引入插件侧逐条流式协议。
- 使用查询 ID 丢弃过时响应；由宿主统一限制数量、排序和结果归属，动作只能指向提供结果的插件及其合法操作。
- 搜索事件只发送给可信 Shell，不能广播给未来的第三方视图。

验收：原有两个示例命令继续可用；静态命令无需启动插件进程；相同局部结果 ID 在不同 Provider 间不冲突；查询变化后旧结果不覆盖新结果。

### 3. 支持多插件并行与搜索取消

交付范围：

- 拆分注册表锁与插件运行状态锁，不在持有全局锁时等待插件 RPC。
- 为搜索增加按请求取消能力，区分搜索取消、调用超时和插件停止。协作取消的具体消息及不合作插件处理策略通过 ADR 确定。
- 扩展 Go SDK，让搜索处理可接收取消信号；安装、卸载、停止与在途请求具有明确的生命周期边界。
- 提供两个独立示例 Search Provider：一个快速返回，一个可配置延迟及失败，用来验证协调行为。

验收：

- 快 Provider 的结果先显示，不等待慢 Provider；耗时插件不阻塞其他插件的查询。
- 连续输入能取消或废弃旧查询；协作取消搜索不终止同一进程中的无关请求。
- 一个 Provider 超时、崩溃或返回无效数据时，其他结果与 Shell 仍可用。
- 卸载或停止插件后不出现悬挂请求、数据竞争和迟到结果复活。

验证方式：真实子进程集成测试覆盖并行、取消、乱序响应及失败隔离，配合 Go 竞态检查；记录搜索延迟，目标与实测值分开报告。

### 4. 完成插件 UI 隔离原型

交付范围：

- 使用最小本地测试页面验证隔离文档或独立 WebView，先确定 Wails v3.0.0 能否建立受限安全上下文。
- 检查默认 Wails Bridge、宿主绑定及事件是否会进入客体视图。独立窗口本身不视为隔离成立。
- 验证资源来源、CSP、导航限制和消息来源身份；原型仅开放必要的无敏感数据消息，例如 ready / close。
- 验证窗口关闭、页面异常、键盘焦点及输入法，不依赖插件 UI 实现宿主恢复入口。

验收：客体页面无法直接调用宿主 `Install`、`Execute` 等完整绑定，不能读取其他插件资源；异常不会破坏 Shell。通过实际负向探测证明边界，并在 ADR 中确定承载方案。

若目标 WebView 无法阻断默认宿主桥接，应记录具体限制并选择替代承载方式；不将仅能加载页面的原型标记为安全隔离完成。

## 本轮完成标准

两个独立进程 Provider 能被动态发现、并行查询并在同一面板展示；旧查询和故障不破坏当前搜索；插件 UI 隔离原型有可复现的验证结果和承载决策。同步更新 Manifest Schema、协议文档、SDK 示例与启动说明。

本轮集中验证上述机制。SQLite、设置中心、完整插件管理 UI、插件市场、Node.js 运行时及 AI 能力放在后续迭代。

## 原生 UI 边界验证交付

2026-11-05：核实 Wails 3.0.0 的 macOS 包装未提供可取消导航决策，因此保留现有 iframe 逻辑探测，新增独立、无 Wails Bridge 的 WKWebView 开发验证宿主。资源先冻结为有归属和预算的只读快照，原生 Scheme 仅访问该快照；导航决策阻止初始文档以外的导航和新窗口；消息超过预算后撤销。`make ui-probe` 正常与洪泛两种模式在本机实测通过，HTTP 正对照可达但逃逸端点没有收到请求。独立客体可使用自己的临时 localStorage，不能沿用 iframe 的存储不可访问断言。见 [ADR 0012](adr/0012-native-ui-boundary-probe.md)。

下一轮优先定义 UI 资源声明与宿主会话生命周期，绑定包指纹、启用状态及失效撤销，再接入隔离客体进程。还需覆盖权限默认拒绝、渲染异常/资源耗尽和其他平台；本轮不开放第三方任意页面。

## UI 会话绑定与撤销交付

2026-11-05：内核准备接口固定从已安装包 `ui/` 子目录创建会话，前后校验包指纹，绑定实例与启用状态。关闭、禁用、停止、重载、升级、卸载、配置变化及检测到文件变化均撤销资源和消息；失败回退同一指纹不会复活旧句柄。原生宿主逐次从会话读取资源，正常关闭、洪泛及真实内核禁用三种模式均实测通过。此接口仍不开放给 Wails、进程 RPC 或 manifest。见 [ADR 0013](adr/0013-ui-session-revocation.md)。

下一轮优先将原生客体抽为可监督的独立进程：定义握手、会话私有管道、退出/超时回收及启动失败恢复，再开放受限 UI 资源声明。权限默认拒绝、渲染异常与资源耗尽、其他平台仍是前置条件，不能由固定夹具验证推导为任意恶意页面可安全运行。


## UI 独立客体进程监督交付

2026-11-05：新增内部 `uiprocess`，父进程持有内核会话，宿主指定的独立原生客体通过私有 stdio 管道逐次获取资源和提交窄消息。启动等待管道与页面握手，启动失败撤销并回收；取消、运行超时、会话撤销、协议异常和预算耗尽均触发退出，宽限后强制终止并等待回收。开发验证三种模式已在独立进程通过，真实子进程测试覆盖失败、挂起、并发停止和故障隔离。见 [ADR 0014](adr/0014-ui-guest-supervision.md)。

下一轮先定义受限 UI 资源声明和协议兼容语义，建立公开入口前补齐权限默认拒绝、渲染异常与资源耗尽策略；继续保持第三方页面与可信 Shell 分离。本轮没有向普通插件开放 HTML，也没有实现操作系统安全沙箱。


## 受限 UI 声明与默认拒绝交付

2026-11-05：`contributes.uiViews` 支持视图 ID、包内 HTML 入口、必填桥版本及空权限声明，最多 4 个。内核准备接口改为按声明 ID 打开，绑定视图与桥版本；缺失声明、直接传入路径、不兼容版本、未知字段和非空 UI 权限均拒绝。原生验证夹具已使用声明，正常、洪泛和禁用三种模式通过。后端应用用途声明不赋予 UI 能力，可信组件不会因 UI 声明获得 HTML 加载语义。见 [ADR 0015](adr/0015-declared-ui-views.md)。

下一轮先处理渲染异常、页面挂起和资源耗尽的观测与回收，再接日常桌面宿主的受限窗口入口及焦点/输入法实测。当前声明不开放普通 Shell 的第三方 HTML，通用权限授权与操作系统沙箱仍未实现。


## 原生渲染故障与响应预算验证

2026-11-05：原生开发客体将调用脚本异常、渲染退出、导航失败、响应超时和总期限结束记录为固定故障类别，故障时撤销会话并结束窗口。响应检查不依赖页面上报心跳，原生层最多保持一个待完成的 JS 探测，用单调时钟判断超时。新增脚本抛错、死循环、可响应慢页面三种实测；前两种故障后同一内核可继续打开正常客体，六种模式全部通过。见 [ADR 0016](adr/0016-ui-renderer-failure-probes.md)。

下一轮接入日常桌面宿主管理的受限独立窗口入口：保持可信组件与第三方 HTML 分离，明确开发期开关和可执行文件分发方式，并验证关闭、焦点和输入法。CPU/内存硬配额、渲染进程真实崩溃注入及其他平台仍待实现；现有响应检测不构成资源安全沙箱。

## 独立窗口 AppKit 事件派发修复

2026-11-05：用户实测发现独立窗口显示后约两秒黑屏、无法操作。原生客体只运行 NSRunLoop，能够处理 WebKit IPC 与定时器，却未取出并派发 AppKit 的窗口、键盘和鼠标事件。现改为 nextEvent / sendEvent / updateWindows，并在每次循环使用局部 autoreleasepool；保留独立的响应检测和撤销检查。

新增固定无害原生事件标记 `eventLoopResponsive`，六种探测与普通客体回归均检查事件派发；在临时源码副本换回旧循环，新回归失败，修复实现通过。外部原生程序由 TestMain 构建，Go 的测试缓存不能可靠反映其源码变化，原生检查命令已增加 `-count=1`。修复不改变权限、桥接和资源协议。更新后需退出旧验收实例，再运行 `make ui-acceptance` 点测真实输入与标题栏操作。

## 用户调整目标：主窗口呈现与按键拆出

2026-11-06：用户明确 uTools 式交互为默认在主窗口打开插件页面，再以快捷键拆成独立窗口；拆出后不受主窗口显隐控制。该指令优先于此前默认独立打开的开发方案。

已接入逻辑主面板：HTML 客体以无边框非激活面板替代搜索面板的展示位置，保持鼠标屏幕居中、顶部 20% 比例定位和失焦隐藏。Command + Space 显隐当前面板；Command + Shift + D 或原生「独立」按钮把同一个 WebView 移入普通窗口，不重新加载，随后 Command + Space 继续控制搜索面板。返回按钮关闭当前客体并恢复搜索。

这是两个原生窗口互斥展示的逻辑主面板，不是跨进程 NSView 嵌入；独立进程、资源快照和窄桥保持原有边界。设置、插件管理仍使用可信 Shell 组件，此次拆出仅覆盖声明式 HTML 视图。详见 [ADR 0022](adr/0022-main-panel-detach.md)。自动化覆盖控制路由和原生文档保留，真实三屏、全屏、中文输入法与键盘组合仍需点测。
