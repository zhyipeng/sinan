# 插件主面板与拆出手动验收

在项目根目录运行：

```sh
make ui-acceptance
```

当前要求 macOS。建议先从托盘退出日常实例，避免两个实例争用 Command + Space；日常配置和插件不会被修改。

命令构建宿主和客体，在系统临时目录准备独立实例，仅安装「设置」「插件管理」「窗口验收」。启动后直接显示插件管理，找到「窗口验收」，点击 **打开 输入测试**。托盘悬停文字包含「临时验收」，用它区分日常实例。

搜索面板输入「窗口验收」或 `window`，回车进入主面板中的插件页；顶部应有「返回」和「独立 ⌘⇧D」。也可从管理界面打开。

## 点测顺序

| 操作 | 通过标准 |
| --- | --- |
| 搜索并打开输入测试 | 无边框主面板显示插件，顶部操作区约 50 高，不出现第二个普通窗口 |
| 输入中文、选词、回车换行，再输入英文 | 不丢字、不误关闭；组词状态正确 |
| Command + Space 两次 | 插件面板隐藏再显示，文本保留 |
| 点击其他应用后再次呼出 | 失焦隐藏；呼出恢复原页面 |
| 将鼠标移到三块屏幕分别呼出 | 鼠标屏幕横向居中，顶部位于可用区域 20%，包括左侧 DELL U2719D 和 DELL P2723D |
| 在全屏应用上呼出 | 面板可见可输入，不切换到其他桌面 |
| 输入一段文字后按 Command + Shift + D | 变为可拖动、带标题栏的独立窗口，原文字保留 |
| Command + Space 呼出和隐藏 | 搜索面板独立显隐，已拆出窗口保持显示 |
| 搜索同一命令或从管理界面打开 | 聚焦原独立窗口，文本和拖动位置保留，不重建窗口 |
| 最小化独立窗口后搜索打开 | 恢复同一窗口 |
| 关闭独立窗口后重新打开 | 新页面回到主面板，旧文本清空 |
| 点击主面板顶部返回 | 当前插件关闭并回到搜索 |
| 点击主面板顶部独立按钮 | 与拆出快捷键效果一致 |
| 点击页面关闭或独立窗口标题栏关闭，再打开 | 正常回收并可重新打开 |
| 点击模拟卡死，再次确认 | 当前页面被回收，搜索仍可用 |
| 拆出后从插件管理禁用、卸载 | 对应窗口关闭，其他窗口与主面板保持可用 |
| 从临时实例托盘退出 | 宿主、客体退出并清理临时目录 |

设置、插件管理也支持拆出，无需开启第三方 HTML 加载：

1. 搜索「设置」，录入一组新的呼出快捷键但不保存，再按 Command + Shift + D。应出现标题为「设置」的独立工具窗口，待保存草稿仍在。
2. 在独立设置页继续录入、取消、保存快捷键，均应正常。录入过程中 Command + Shift + D 应被录入控件接收，不误拆出；拆出后 Escape 可取消录入。
3. 用实际生效的呼出热键显隐搜索面板，设置窗口应保持显示；切换应用后也不自动隐藏。
4. 在新主面板打开「插件管理」，输入一个测试目录但不点检查，按拆出按钮。输入应保留，设置窗口不受影响。
5. 拖动、调整大小、关闭任一独立窗口，另一个窗口和搜索面板应继续可用。关闭设置窗口后重新打开应是新页面，不保留未保存草稿。
6. 设置和插件管理不应出现“禁用”“卸载”入口。使用临时实例的「窗口验收」普通插件验证禁用、卸载会关闭对应窗口；设置和管理页应保持可用。

页面不持久保存输入；只在关闭再打开后检查输入清空。「模拟卡死」会丢失当前输入。真实输入法、键盘快捷键、三屏和全屏需要人工点测，浏览器模拟不能替代。

## 日常检查与按需 UI 验证

日常回归只运行无弹窗检查：

```sh
make test
```

`make test` 强制关闭真实 WebView 测试，仍覆盖会话、并发和无界面子进程的故障回收。真实桌面 UI、原生探测、下文浏览器交互回归和手动验收不属于日常回归，仅在用户明确要求对应 UI 验证时运行。

按需原生验证会打开真实窗口：

```sh
make ui-probe
```

原生验证覆盖固定原生探测及 AppKit 事件队列派发；原生外部客体测试使用 `-count=1` 禁用测试结果缓存。它们不能替代上表的人工操作。请记录失败步骤、macOS 版本、显示器与全屏状态、输入法，以及是否可以重新打开窗口；无需发送实际输入的私人文本。

正常托盘退出及终端 Ctrl+C / SIGTERM 均走宿主关闭回调，先回收客体再删除临时环境；准备失败也清理。SIGKILL 或系统异常终止无法保证回调执行，可能留下 `sinan-ui-acceptance-*` 临时目录。此命令不调用日常开发插件准备脚本，不访问日常插件根目录，也不恢复之前移除的 demo 插件。

## 呼出事件串窗回归

拆出设置页或插件管理，保留未保存的输入。连续呼出/隐藏主搜索框，再搜索和打开其他界面：独立页应保持原界面和草稿；新主窗口应仍能正常搜索与拆出。该项修复覆盖 launcher:show 重置串窗和 view:detached 角色误广播。

浏览器自动回归（另一个终端先运行前端 dev 服务）：

```sh
npm --prefix apps/desktop/frontend run dev
npm --prefix apps/desktop/frontend run test:windows
```


## 自定义窗口独立快捷键

在设置页底部「窗口独立快捷键」录入新组合并保存；它只在当前插件页中生效。若修改过，本文的 Command + Shift + D 应替换为实际保存的组合。

- 尝试保存与呼出键相同的组合，应提示冲突并保留原设置；反向修改呼出键也应拒绝相同组合。
- 保存 Ctrl + Option + Shift + U 等测试组合后，旧拆出键不再生效，新组合能拆出设置及插件管理，未保存输入保留。
- 录入控件中输入拆出组合应成为草稿，不应拆出页面；恢复默认后点击保存，再次打开设置确认持久化。
- 预先拆出设置页，再打开 HTML「窗口验收」；在独立设置页修改拆出键，回到 HTML 页面，新键应生效且原有输入保留，顶部按钮提示同步。
- 连续更改、跨窗口修改时不得以旧修订覆盖新组合；改变拆出键不改变呼出键，切换应用后也不应拦截其他应用按键。

## 系统插件损坏恢复

仅在临时验收目录操作：安装设置/插件管理后将其 manifest.json 改成无效 JSON，在宿主恢复入口填写项目内对应系统插件目录，先检查再恢复。分别验证运行中损坏和退出后重新启动的情况。恢复后应可重新打开对应页面，设置和插件管理仍没有禁用、卸载入口。检查后再改动候选或安装目录，恢复应要求重新检查。不要在日常插件目录构造故障。

## JSON 格式化工具

JSON 工具已迁至独立的官方插件仓库。先按 [README 的 JSON 安装步骤](../README.md#json-格式化插件) 构建并显式安装，再用 `make dev-ui` 开启 HTML 窗口；该命令只准备三个内置插件，不自动安装 JSON。日常实例仍默认关闭 `-plugin-ui`，验收请使用开发实例；安装前须退出使用同一开发目录的旧实例。

1. 搜索 JSON，回车打开编辑器；输入包含 `900719925474099312345` 的合法 JSON，点击格式化 / 压缩，数字和键顺序应保持。Command/Ctrl + Enter 格式化，加 Shift 压缩。
2. 输入错误 JSON，保留原输入并提示行列；编辑界面没有英文自动纠正。嵌套、输入和输出超限应返回错误。
3. 等待“草稿已保存”，关闭再打开，退出宿主再启动，草稿应恢复；未保存状态下立即关闭不保证保留最后 700 ms 的修改。
4. 输入后拆出窗口，继续格式化；再次呼出主搜索框，独立窗口内容不变。确认拆出前后均能保存草稿。
5. 仅在临时目录构造 revision 冲突或损坏数据文件：保存失败保留输入并提示，不能静默覆盖文件；显式“载入已存草稿”恢复已保存版本。读取失败仍可格式化，暂停自动写入。

可重复原生自动化：按 [README](../README.md#json-格式化插件) 设置 `SINAN_JSON_PLUGIN_PACKAGE` 和 `SINAN_NATIVE_UI_TEST=1` 后运行对应测试（使用本机 Go 1.26 工具链及项目 macOS 编译标志）。浏览器 UI 夹具已迁至官方插件仓库，在该仓库运行 `node plugins/json-tool/tests/serve.mjs`，再执行 `ego-browser nodejs < plugins/json-tool/tests/ui-regression.js`；该夹具不验证真实桥安全边界。以上均仅在用户明确要求 UI 验证时运行。

## 插件私有数据管理

仅用临时/开发实例验收，不清理日常数据：

1. JSON 工具输入内容，等待草稿已保存。在插件管理底部展开“插件数据”，应显示插件、文档字节数；不会展示正文。
2. 点击清空，确认区应滚入视野并默认聚焦取消；取消后数据和页面保留，焦点回到原按钮。
3. 在确认前让 JSON 再保存一次，旧确认应拒绝；列表刷新后重新确认才能清空。清空后旧 HTML 页面关闭，重新打开 JSON 得到空草稿，不会自动回写旧内容。
4. 卸载普通插件后仍能看到其私有文档，标记“未安装”；确认后可删除残留。损坏包未注册同样标记未安装，不能据此判断包目录已卸载。
5. 仅在临时目录模拟损坏 JSON、超大普通文件、符号链接和目录：前两者可清理，后两者按钮禁用，不递归删除或修改目标文件。设置和插件管理仍不能禁用、卸载。

数据占用仅统计私有 JSON 文档的逻辑字节，不含设置、使用历史、包或缓存；文件异常或权限不足不能被当作数据已清空。CLI 的 data 列表与 clear-data 操作也仅限该文档。

## 主题切换（仅在明确要求交互验收时执行）

1. 设置 → 外观切换浅色、深色、跟随系统；重启确认选择保留。
2. 将设置、插件管理和 JSON 工具拆出独立窗口，修改主题，确认搜索和各窗口同步且草稿、查询不丢失。
3. 跟随系统时切换 macOS 明暗，确认页面及标题栏变化；手动浅/深色时保持所选外观。
4. 保持 JSON 输入内容切换主题，确认不重载、不关闭窗口，仍能继续编辑、格式化和保存。

本轮仅执行不弹窗的自动检查，以上实机结果待记录。

## 设置快捷键（仅在明确要求交互验收时执行）

在搜索、插件管理、JSON 工具中按 Command + ,（其他平台可信窗口为 Ctrl + ,），确认进入设置；设置已拆出时应聚焦原设置窗口并保留草稿。JSON 工具已拆出时保留其文档与窗口；附着于主面板时按正常离开页面处理。快捷键录入中、组词中及带 Shift / Alt 时不触发设置导航。
