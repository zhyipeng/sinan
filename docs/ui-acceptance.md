# 独立窗口手动验收

在项目根目录运行：

```sh
make ui-acceptance
```

当前要求 macOS。建议先从托盘退出日常实例，避免两个实例争用 Command + Space；日常配置和插件不会被修改。

命令构建宿主和客体，在系统临时目录准备独立实例，仅安装「设置」「插件管理」「窗口验收」。启动后直接显示插件管理，找到「窗口验收」，点击 **打开 input**。托盘悬停文字包含「临时验收」，用它区分日常实例。

## 点测顺序

| 操作 | 通过标准 |
| --- | --- |
| 打开 input | 出现独立「窗口验收」页面，输入区可输入 |
| 输入中文、选词、回车换行，再输入英文 | 不丢字、不误关闭；组词期间显示「正在组词」，完成后恢复输入状态 |
| 点击清空 | 文本清空，字符计数归零，输入区重新获得焦点 |
| 用 Command + Space 呼出/隐藏搜索 | 搜索面板工作正常，独立窗口仍可继续输入 |
| 切到全屏应用，再从验收实例呼出并打开窗口 | 窗口可见、可操作，不被留在不可见的 Space |
| 点击页面的关闭窗口，然后从插件管理重新打开 | 正常关闭，随后可再次打开 |
| 点击原生标题栏关闭按钮，然后重新打开 | 同样正常关闭与回收 |
| 点击模拟卡死，再次点击确认 | 页面在响应超时后被回收，宿主仍能呼出并重新打开 input |
| 打开窗口后，在插件管理禁用窗口验收，再启用 | 已有窗口关闭；启用后可重新打开 |
| 最后打开窗口，再卸载窗口验收 | 窗口关闭，插件从当前临时实例移除 |
| 从临时实例托盘退出 | 宿主和客体退出，临时目录清理 |

搜索面板每次呼出会返回搜索页；需要重新打开窗口时，点击管理插件入口。卸载测试后，再次运行同一命令会建立全新的验收实例。

只在窗口关闭并重新打开后检查输入清空；页面不持久保存输入内容。「模拟卡死」会使当前页面的未保存输入丢失，两次点击是为了避免误触。浏览器预览不会执行死循环，也不能验证原生输入法、窗口关闭和全屏行为。

## 自动检查与记录

```sh
make test
make ui-probe
```

自动检查覆盖会话、并发、故障回收和固定原生探测，不能替代上表的人工操作。请记录失败步骤、macOS 版本、显示器与全屏状态、输入法，以及是否可以重新打开窗口；无需发送实际输入的私人文本。

正常托盘退出及终端 Ctrl+C / SIGTERM 均走宿主关闭回调，先回收客体再删除临时环境；准备失败也清理。SIGKILL 或系统异常终止无法保证回调执行，可能留下 `sinan-ui-acceptance-*` 临时目录。此命令不调用日常开发插件准备脚本，不访问日常插件根目录，也不恢复之前移除的 demo 插件。
