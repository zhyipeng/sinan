# ADR 0030：插件私有数据的查看与清理

日期：2026-11-09。状态：已实施。

## 原因

上一轮已实现插件私有 JSON 文档，但没有管理占用及卸载残留的入口。用户选择优先补齐数据管理，并要求清理前明确确认。

## 决策

- 日常界面留在可信 system.plugin-manager，版本提升为 0.5.0。新增默认折叠的“插件数据”，按需读取占用、安装状态及文件异常状态；不读取或展示文档值。
- 清理与卸载分开。卸载继续保留私有文档，管理列表可以清理未安装插件的残留；文件损坏导致插件未注册时也显示“未安装”，不将其误判为已完成卸载。
- 用户点击清空后显示插件名、会关闭页面及不可撤销提示，二次确认才调用内核；取消无副作用。确认区滚入可见区域，默认聚焦取消，取消后焦点返回原操作按钮。
- 清理请求携带列表中检查得到的文件状态指纹；数据自上次查看后变化则拒绝，刷新后重新确认。失败保留文件与页面会话，不放宽系统插件禁用/卸载保护。
- 只删除该插件固定 JSON 文档文件，不清理插件包、配置、使用历史、缓存或其他插件数据，不递归删除目录。符号链接、目录及无法读取的文件不提供清理凭据；损坏 JSON 和超大普通文件仍支持清理。
- 成功删除后，在释放内核变更锁之前撤销该插件所有 HTML 会话，避免旧自动保存或旧 revision=0 请求重建数据。新页面从空文档读取，revision 重新从 0 开始。已进入写入事务的操作先完成，旧清理指纹随即失效；撤销后不再接收旧调用。

## 接口与边界

可信 Shell 增加 PluginData() 元数据列表和 ClearPluginData(id, token)。列表字段仅含 id、name、installed、bytes、corrupt、token；bytes 是文件逻辑字节数，不是文件系统分配块占用。未安装包以 ID 代替名称。宿主关闭后接口拒绝调用。

文件状态指纹包含文件身份（macOS/Linux 的设备与 inode、Windows 的卷与文件编号）、大小、修改时间、类型及有界内容摘要；内容与时间相同的替换文件也会使旧确认失效。正常文档完整计算摘要；超过 128 KiB 的异常文件最多读取头尾各 64 KiB，避免清理界面因大文件无界读取。列表最多检查 2048 个目录条目，禁止扫描任意路径。它用于协调宿主内的显式操作，并非针对可任意写磁盘、伪造时间戳的可信原生插件的 OS 安全边界。

管理接口不进入 UI 桥 2，页面仍只能读写本插件文档，没有跨插件管理能力。原有后端 API / UI 桥版本不变。

CLI 增加 data 与 clear-data ID 检查指纹，需先退出同目录宿主、释放独占锁。CLI 不输出文档值；显式提供检查指纹执行清理，不提供绕过检查的 force 模式。

## 验证

存储与内核回归覆盖：元数据无正文、正常清空、写入后旧确认失效、损坏/超大文件、符号链接及目录拒绝、清理失败保留页面和其他数据、旧会话不能回写、卸载残留可清理、核心配置与历史保留，以及受保护插件策略不变。

真实 WebView 持续自动保存时执行清理，验证会话撤销、客体退出及文件不再创建。浏览器回归覆盖二次确认、取消、变化拒绝后重新确认、已安装/未安装数据清理、空态和不可清理文件。CLI 在临时目录验证查看、旧指纹拒绝和孤立数据删除。没有清理日常目录。
