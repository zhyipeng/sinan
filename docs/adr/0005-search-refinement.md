# ADR 0005：拼音、增量索引与宿主使用历史

日期：2026-11-04。状态：已实施，应用插件版本 0.2.0，仅在 macOS arm64 验证。

## 职责与兼容

拼音别名和应用目录扫描仍位于 `system.app-search`。使用历史归宿主，适用于所有成功执行的命令及动态结果动作；插件不能自行提供历史加权。此次不改变插件协议、Manifest 字段或 SDK 接口。

## 拼音

索引含汉字的名称时，使用 macOS Foundation 的 Mandarin-to-Latin 和去音调变换，建立带空格拼音、连续拼音及首字母别名。例如“计算器”可通过 `ji suan qi`、`jisuanqi`、`jsq` 查询，保留原中文标题及英文文件名匹配。不引入额外拼音字典依赖；多音字依赖系统转换结果，不保证自定义应用名的全部读音。其他平台暂不提供此转换。

## 增量刷新

一分钟到期后的下一次查询仍扫描应用目录，增删条目随下一次扫描反映。对未变化的 Bundle 复用元数据、匹配别名及已读取图标，依据入口真实路径、Bundle/Info.plist/Resources 的修改时间和大小判断变化；重复目录、链接以及无效 Bundle 按真实路径去重。

未变化的元数据最多复用五分钟，避免深层本地化文件变更因目录时间不变而长期漏检。手动“刷新应用索引”绕过所有元数据与图标缓存。取消重建不发布半成品，旧索引保留。读取 Info.plist 直接从文件获取，避免 NSBundle 的对象缓存掩盖应用更新。

这不是文件监听或后台扫描。第一次仍需读取元数据和建立拼音别名；冷启动延迟尚无达标保证。

## 使用历史

- 仅宿主确认成功执行后记录；失败、取消、被移除实例的执行不计入。
- 持久化为插件安装根目录下 `.sinan-state/usage.json`。该目录不匹配插件 ID，不进入插件发现。保存动作 `(pluginId, commandId, input)` 的 SHA-256 摘要、次数及最后使用时间，不保存原始输入、查询、标题、路径或输出。
- 历史仍是本地用户行为数据，摘要不等于加密或匿名化。继承可信原生进程的边界，不宣称能阻止同一用户权限的原生代码读取它。
- 单文件最多 4096 个动作、加载上限 1 MiB，目录模式 0700、原子替换文件模式 0600。损坏文件退回空历史；保存失败不改变命令已经成功的结果。此处采用有界 JSON，尚未引入规划中的 SQLite 与通用插件存储服务。
- 历史权重结合对数频率和近期使用衰减，最多增加 0.025。插件动态基础分仍被限制到 0.8，最终动态分至多 0.825；应用名称的精确、前缀等匹配档位保持更大的分差。相同相关性时优先常用和最近使用的动作。
- 排名只作用于各 Provider 已返回的最多 20 条候选，不能从未返回的应用条目中召回历史结果。跨 Provider 统一排序由宿主完成。
- CLI 新增 `clear-history`，原子清除记录。与现有安装状态一样，当前不支持多个宿主进程同时写同一个插件根目录；执行清理前退出桌面实例，随后重新启动。

## 验证

竞态和单元测试覆盖拼音/首字母、中英文匹配共存、缓存复用、Bundle 变化与删除、强制刷新、成功动作记录、失败动作忽略、重启保留、排序调整、频率/时间衰减、条目上限、私有文件模式和清除记录。独立真实进程验证 `jisuanqi` / `jsq` 查询返回计算器。实际 CLI 在不同进程间执行、查询与清理，验证基础分 0.85 在成功执行后升为约 0.861，清理后恢复 0.85。`make test`、`go vet ./...` 与 `make package` 通过。

一次 macOS 26.6 arm64 进程实测：首次 `jisuanqi` 约 276 ms，随后 `jsq` 约 1.8 ms、`calculator` 约 0.1 ms。这不是 P95，首次索引仍未达到规划目标。

后续需要明确设置与存储服务、跨进程状态协调、Provider 候选召回和索引冷启动策略，再扩展历史管理 UI、持久索引或自定义目录。
