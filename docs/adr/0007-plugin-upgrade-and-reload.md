# ADR 0007：开发期插件升级与重载

日期：2026-11-04。状态：已实施，运行验证平台为 macOS arm64。

## 变更检测与重载

插件包采用 SHA-256 内容指纹，覆盖相对路径、文件内容和可执行标记；不依赖修改时间或版本号。沿用 64 MiB / 2048 条目的限制，拒绝符号链接与特殊文件。指纹用于识别包内容，不是签名或可信身份认证。

`Refresh` 在启动发现、重新呼出及手动刷新时检查安装目录。已注册插件发生变化时标记 `changed`，保留原注册信息和当前实例，不立即替换。未运行的变更插件会拒绝隐式激活，须先重载。删除目录仍会移除注册并结束旧实例。没有后台文件监听。

`Reload(ID)` 校验磁盘包，使用现有信任记录初始化候选进程，再退休旧实例并发布新实例。失败时保留当前注册和仍在运行的旧进程。它不会撤销用户已经直接修改的安装文件，也不能保证旧进程读取的资源文件不受外部修改影响。若插件不允许两个进程同时初始化，重载可能失败；可显式停止后再重载。可信组件 UI 仍随宿主构建，重载安装包不会执行其中的 JS 或刷新宿主组件代码。

## 升级事务

`PreviewPackage` 提供名称、目标版本、已安装版本、源包指纹和已注册包指纹。桌面 `ApplyPackage` 同时比较源与目标基线，检查后包被修改、目标被其他操作替换，均须重新检查。首次安装继续支持不执行初始化的按需激活模型；已有插件升级按以下顺序执行：

1. 验证已安装文件仍匹配已注册指纹；磁盘已有外部改动时要求先重载或还原，避免将不明状态当作可恢复旧包。
2. 复制候选包到同文件系统临时目录，重新校验清单、入口、大小、内容和检查指纹。
3. 写入升级日志，退休旧实例并停止进程，将旧目录改名备份，再将候选包放到原路径。
4. 应用信任状态，对原生插件执行最长 2 秒的初始化握手，并检查声明的搜索能力；不调用业务命令。目录内容在初始化中被改变也会拒绝。
5. 成功后记录提交并发布新实例，清理事务目录。失败则恢复旧目录和原信任状态；原先运行中的插件会尝试重新启动。

可显式安装同版本的新内容，也允许用户明确选择的降级；未变化的包不重启进程。原生升级每次需要重新确认信任。声明式与原生模式转换也恢复或清除对应信任状态。

配置与使用历史位于宿主 `.sinan-state/`，不随包切换或回退；相同动作身份继续使用原有历史。退休实例采用新的注册实例标识隔离，在途请求失败、迟到响应不能复活为新版本结果。其他插件调用不等待候选初始化。

握手通过不等于业务功能全部正确。成功升级后不保留长期旧版归档，也不会在未来任意业务错误时自动回滚。可信原生代码的初始化副作用不属于文件事务的回滚范围，仍不提供系统沙箱。

## 中断恢复与目录独占

事务保存在 `.upgrade-*` 内，使用原子替换的 `transaction.json` 记录提交状态。启动时，未提交事务恢复旧目录及旧信任状态；已提交事务清理旧备份。无效日志保留现场并给出诊断，不尝试猜测目标路径。恢复失败的已知插件会隔离出注册表；未解决的事务会阻止继续修改相关插件包，无效且无法识别归属的日志则阻止包变更，须修复现场后重新启动。此恢复针对进程中断，不承诺完整的断电持久性。

同一插件根目录在宿主生命周期内持有 `.sinan-state/runtime.lock` 的操作系统独占锁，避免第二个宿主误恢复仍在进行的事务，以及多个内存配置实例互相覆盖。关闭时先拒绝新调用、结束插件进程并等待在途调用及历史写入，再释放锁。进程退出后 OS 自动释放锁；文件本身保留，无需删除。

macOS / Linux 使用 flock；Windows 使用 LockFileEx，Windows / Linux 仅完成存储包交叉编译，未运行验证。锁仅约束遵循本约定的宿主，不能限制同一用户的任意原生代码或不支持此锁的旧版宿主。它实现单写实例，不是多宿主并发写入协议。

因此 CLI 与桌面不能同时打开同一根目录，连只读命令也需先退出桌面；正在运行时使用桌面的恢复入口检查、重载和升级即可。不同根目录可以同时使用。

## 产品入口与开发工具

宿主最小恢复入口保留原有停止、卸载，再追加重载。目录安装入口先“检查”，展示版本变化，再安装或升级；原生信任选择与此次检查绑定，包变化时必须重新检查和确认。完整插件管理业务 UI 仍计划迁移至插件层。

CLI 新增 `inspect 目录`、`upgrade 目录`、`reload ID`。`make demo` 对仓库内已安装示例调用升级，不再要求手动卸载；仅对仓库自带、现场编译的原生插件使用信任参数。

## 验证

真实进程与竞态测试覆盖成功升级、失败初始化回退、声明式转原生失败后信任撤销、配置/历史保留、旧查询退休、其他插件响应、同版本改动、同大小/时间的二进制变化、显式重载失败保留 PID、检查后的包与目标变化、中断恢复，以及跨进程目录锁与退出释放。

浏览器使用实际 Shell、模拟 IPC，覆盖重载按钮、版本预览、原生信任、检查后源变化拒绝、重新检查成功升级；按 680 DIP 宽度检查布局，并回归设置、键盘导航及直接执行。

实际 CLI 端到端验证通过：升级成功与初始化失败回退均保留配置和历史；占用目录时第二个 CLI 被拒绝；强制终止正在升级的 CLI 后，下次启动恢复旧版本并可继续执行命令。`make test`、`go vet ./...`、前端类型检查和打包通过；目录锁另完成真实子进程测试及 Windows/Linux 存储包交叉编译。

重复执行本机示例准备脚本的验证通过：所有未变化包均保持未激活状态，配置与历史文件字节保持不变。
