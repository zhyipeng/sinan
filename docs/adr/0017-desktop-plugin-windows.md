# ADR 0017：桌面开发期独立插件窗口

- 状态：macOS 开发入口已接入；默认关闭，尚非公共分发能力
- 日期：2026-11-05
- 后续：[ADR 0020](0020-search-opens-independent-views.md) 已增加独立视图命令的搜索入口；本文仅从管理界面打开的描述为当时阶段记录。

## 原因

固定探测程序已经验证资源、窄消息和进程回收，但没有可供日常桌面打开的普通客体。需要复用验证过的原生机制，同时将探测代码和动作排除在普通页面之外，并明确窗口退出与宿主退出的所有权。

## 决策

- 将原生运行器移到 `internal/plugin/uihost`，供开发探测和新的 `apps/ui-host` 共用。普通可执行文件固定为宿主旁的 `sinan-ui-host`；父进程不能接受页面传入的可执行文件、路径覆盖、脚本或权限。
- `make build` 构建客体，`make package` 将它放入 app 的 MacOS 目录。桌面默认关闭窗口入口，`-plugin-ui` 或 `make dev-ui` 显式启用；仅当前 macOS 开发阶段使用。helper 缺失或平台不支持时提供诊断，保留 Shell 和恢复入口。
- 可信 Shell 获得 `PluginUIEnabled` 和 `OpenPluginView(pluginId, viewId)`，插件管理 0.3.0 在已有管理操作之后展示声明视图的打开按钮；禁用或待重载包不能点击。内核仍是最终检查点，不信任前端状态。`commands[].view` 和静态可信组件注册不改变，第三方 HTML 不进入 Shell，也不获得这两个 Wails 方法。
- 新增 `uiwindows.Controller`，同一插件/视图从开始启动到进程回收期间只能打开一次，防止双击启动多个客体；关闭后释放槽位，可再次打开。启动等待页面 ready，启动失败撤销并释放预留。内核原有每插件/每宿主会话上限继续生效。
- 控制器有独立于搜索、面板失焦的上下文；打开窗口不会因 Shell 隐藏而被取消。禁用、停止、升级、卸载和内核撤销通过既有会话通知客体退出。宿主退出先取消启动和运行中的客体，等待回收，再关闭内核和目录租约。回收等待不包含可能需要 UI 主线程的退出通知，避免主线程执行宿主关闭时与事件派发互相等待。
- 异步退出后只向可信 Shell 发送 `{pluginId, viewId, failed}`，管理组件提供固定失败反馈。错误不包含页面文本、NSError 或资源内容。启动错误由打开调用直接返回。
- 普通客体开启原生标题栏关闭、缩放和调整尺寸，可获得键盘焦点。红色关闭按钮也提交 close/撤销并结束运行。普通模式不执行 `window.runProbe`，不识别 report / revoke 探测消息，不启用诊断禁用回调。
- 普通窗口保留页面响应探测；取消固定探测程序的 8 秒期限，父监督器暂设 1 小时总期限，作为开发预算。它不是最终空闲/休眠或后台任务策略。
- 延续非持久存储、固定资源 Scheme、CSP、导航与消息来源检查；拒绝 JavaScript 对话框、原生文件选择器及媒体采集请求。页面权限仍为空，没有新增 Host API 授权能力。

## 验证

- 真实子进程控制器测试覆盖同视图去重、声明缺失、禁用/停止撤销、异常退出后重新打开、启动中并发关闭、关闭后拒绝打开及 helper 路径/符号链接拒绝，运行 Go 竞态检查。
- 可选真实原生测试 `SINAN_NATIVE_UI_TEST=1 go test -race -count=1 ./internal/plugin/uiwindows -run TestNativeHost` 使用普通 `sinan-ui-host`。固定页面确认无 Wails Bridge、确认弹窗被拒绝、页面输入框获得焦点；发送探测 report / revoke 不影响插件启用状态，不调用 runProbe，运行超过 8 秒后通过 close 正常关闭。
- `make ui-probe` 保留六种原生探测，并包含普通客体测试；原有脚本错误、卡死恢复等检查继续通过。
- ego-browser 使用真实管理组件和模拟 IPC 检查默认关闭入口、开发开关显示、包变更/禁用防护、声明 ID 打开、窗口失败事件与窄窗口布局，并回归已有搜索、设置、快捷键、管理与恢复流程。这不替代真实桌面鼠标操作和输入法测试。

## 限制与后续

目前入口位于插件管理，而不是普通搜索命令；没有增加 HTML 命令映射或安装任何 demo 插件。视图暂使用固定窗口标题和默认居中，后续再设计命名、定位与尺寸声明。

自动化原生检查只验证页面焦点和协议关闭；中文组词、跨全屏切换和真实标题栏关闭仍需实机回归。CPU/内存硬配额、操作系统沙箱、签名和稳定的第三方公共分发协议尚未完成。普通独立进程不会限制可信原生插件的当前用户权限，也不能由本轮推导为任意恶意页面均安全。
