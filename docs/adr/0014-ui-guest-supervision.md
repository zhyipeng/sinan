# ADR 0014：独立 UI 客体的私有管道与进程监督

- 状态：内部机制与固定原生开发验证已实施；公开 UI 契约待设计
- 日期：2026-11-05
- 声明演进：[ADR 0015](0015-declared-ui-views.md) 已增加受限 Manifest 声明，并将准备接口从入口路径改为视图 ID；本文无声明接口的描述为当时阶段记录。
- 后续：[ADR 0017](0017-desktop-plugin-windows.md) 已提供默认关闭的桌面开发入口和普通客体；本文未接入桌面的描述为当时阶段记录。

## 原因

ADR 0013 的资源与消息可撤销，但原生客体和内核处于同一开发进程。需要验证客体异常退出不会直接终止内核，并在启动失败、撤销和超时时完成进程回收。后端 stdio RPC 是宿主发起调用，不能直接复用为客体请求宿主资源的传输层。

## 决策

- 新增内部 `internal/plugin/uiprocess`，由宿主选择可执行文件绝对路径和参数；每个客体独占一组 stdin/stdout 管道，管道直接绑定一个内核 Session，不接受页面提供插件身份、会话 ID 或资源根路径。
- 当前开发验证以同一个 `sinan-ui-probe` 可执行文件的 `-child` 分支承载 WKWebView。父进程保留临时内核、资源快照、生命周期和 HTTP 正对照，子进程只持有资源/消息代理。私有 cgo 句柄引用代理，不向页面暴露 Wails Bridge。
- 子进程不继承父进程环境，只设置固定 LANG；工作目录为宿主选定可执行文件目录，stderr 丢弃，stdout 只允许协议帧。错误返回固定描述，不回显资源、页面消息、环境或原始协议数据。没有操作系统权限沙箱。
- 帧使用逐行 JSON，字段必须匹配固定大小写，拒绝重复/未知字段和尾随内容；请求序号严格递增。单帧小于 1 MiB，每管道最多 256 个请求、累计返回资源最多 8 MiB；单资源仍受 512 KiB 限制。页面窄消息仍为 4 KiB / 32 条，继承 Session 的 ready / close 语义。
- 初始化只发送入口 URL、固定 CSP 和开发 HTTP 探测地址，不发送整包资源。子进程 hello 版本为 1，页面 ready 必须由内核 Session 接受。Start 等待页面 ready 后才成功，默认启动期限 3 秒；失败撤销会话、强制退出并等待回收。
- 运行期限默认 30 秒，开发原生验证使用 12 秒；这是内部验证预算，尚非公开插件窗口寿命政策。取消、超时、会话撤销、异常退出、协议错误或预算耗尽触发撤销。监听器只发送本地停止信号，不在内核锁内写管道或等待进程。
- 监督器发送撤销通知，默认留出 500 ms 退出宽限；超时 Kill 并通过 exec.Cmd.Wait 回收。管道读写关闭用于解除阻塞；Wait 返回前读循环已结束。重复停止和并发停止均等待同一次退出。
- 客体资源不使用本地回退缓存；撤销后本地代理拒绝新的资源/页面消息，父进程同时拒绝。此前交付的字节无法收回。父进程撤销与子进程收到通知之间存在异步传播窗口，不能再声称跨进程原生入口在内核操作返回前同步关闭。
- 只有固定验证程序配置诊断禁用回调；默认监督器不开放此动作。验证报告仅是最多 4 KiB 的退出诊断，允许撤销后提交，不授予资源或 Host API。父进程独立填写会话失效、HTTP 计数、不同 PID、完成握手和回收结果，不信任客体声称这些条件成立。

## 验证

- 真实子程序测试覆盖正常资源读取、跨归属拒绝、非法页面动作、关闭后拒绝、环境隔离、启动崩溃、无响应、无页面握手、错误版本、重复/未知字段、超大帧、请求/资源预算耗尽、上下文取消、运行超时、异常退出、强制回收、协作撤销和并发重复停止。
- 一个客体故障后可继续运行其他独立会话；宿主逻辑通过 Go 竞态测试。测试子程序采用普通构建，避免 Go race runtime 默认退出延迟影响宽限期；父进程测试使用 `-race`。
- `make ui-probe` 正常、洪泛、真实内核禁用三种模式均通过；各自报告独立 PID、握手完成和进程回收，旧资源/消息失效，HTTP 正对照可达且逃逸端点没有请求。

## 限制与后续

监督器目前只供固定开发验证调用，尚未接入日常 Wails 桌面宿主、manifest、SDK 或后端 stdio API 1。未改变可信系统组件承载方式，也没有完成跨平台 UI 运行时。

进程隔离只限制本进程崩溃传播，不限制当前用户的操作系统权限、进程树、CPU 或内存；WKWebView 自身渲染进程也不能由本监督器预算推导为已具备完整资源治理。公开加载前仍需受限资源声明、权限默认拒绝、渲染异常/资源耗尽策略与真实交互验证。固定页面的负向测试不能证明任意恶意页面可安全执行。
