# ADR 0009：应用索引快照与后台校验

- 状态：已实施
- 日期：2026-11-05

## 原因

应用检索进程首次激活时同步扫描所有目录并读取本地化名称、拼音。进程重启后重复此过程；原有一分钟后的刷新也会持有搜索锁。按后续计划，先优化这两类等待。

## 决策

- 宿主为原生插件提供可选 `initialize.params.cacheDir`，按插件 ID 位于插件根目录的 `.sinan-state/cache/`。创建权限为 0700，创建失败则省略字段，不能阻止激活。包替换不影响缓存；升级、重载和卸载保留此目录，允许离线清理。
- 这是 API 1 的兼容增量：旧插件忽略未知字段；应用插件在旧宿主未提供路径时保持无磁盘缓存运行。不增加权限声明、通用数据 API 或安全沙箱。
- `system.app-search` 0.4.0 自行拥有索引格式、校验及更新。快照保存目录集合（含顺序）、稳定 ID、应用路径、显示名、匹配别名（含拼音）、元数据时间戳及读取时间。图标继续按结果按需读取，查询与历史不进入快照。
- 文件为 `applications-v1.json`，最多 8 MiB、4096 个应用；恢复时校验版本、根目录、路径范围、ID、字段长度及重复条目。无文件、未知版本、损坏、超限或目录配置变化均回退为正常扫描；不把缓存当作配置或可信授权。
- 无可用快照时，首次查询仍同步建立完整索引，取消则不替换旧快照。有快照时，首次查询和超过一分钟后的查询使用现有结果，同时在后台校验目录；同一进程最多一个后台刷新，失败后至少间隔一分钟再尝试。后台任务独立于查询取消，使用 30 秒协作超时，原生元数据调用不能被强制中断。
- 扫描和写盘持有单独的刷新锁；搜索只短暂获取快照锁。替换采用完整快照提交，磁盘使用 0600 临时文件、同步并原子改名。写盘失败仅失去下次重启的加速，不影响当前搜索。
- 手动“刷新应用索引”同步重建，绕过元数据及图标缓存。后台刷新完成后的下一次查询返回新索引，本轮不扩展 Provider 为同次查询二次推送。校验前可能显示已删除的应用，启动仍只接受索引 ID，并检查应用存在及元数据可读。

## 影响与限制

宿主仅管理缓存位置，应用业务仍在插件层。目录是存储约定，可信原生插件仍具备当前用户的文件权限；没有通用缓存总配额。应用路径与名称属于本机数据，不能将快照作为日志输出。

快照减轻重复元数据读取，不消除插件激活、宿主包指纹计算、首次无缓存扫描和图标加载的开销。尚未实现文件系统实时监听、SQLite 或跨进程共享索引。后台变化在下一次查询生效。

## 验证

- Go 竞态测试：阻塞后台元数据读取时连续查询仍可返回缓存结果；新应用与删除应用在后台提交后更新；旧结果不能启动已删除应用。
- 快照损坏、超限、未知版本、目录变化、非法路径/ID、重复项和未来读取时间回退；取消不覆盖快照，手动刷新更新磁盘，缓存写入失败保持搜索可用。
- 真实子进程内核测试：初始化收到缓存目录；升级后目录和内容保留；目录无法创建时仍可激活。全量 `make test` 覆盖现有搜索、生命周期和设置回归。

2026-11-05 在本机 macOS 26.6 / arm64、独立临时插件根目录中，以 `sinanctl search safari` 实测。标准目录索引包含 166 个应用，快照 52,489 字节；无索引快照首查为 702.3 ms。随后每次重新启动 CLI 和插件、保留索引快照的 5 次测量为 44.8 / 43.8 / 43.6 / 43.3 / 43.6 ms，中位数 43.6 ms，均返回 1 项且无来源错误。计时包含宿主加载及包指纹、插件启动和搜索；OS 文件缓存未清空，这不是磁盘冷启动、桌面端到端耗时或 P95，也不表示架构性能目标已经达成。
