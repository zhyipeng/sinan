# ADR 0003：搜索扩展点、请求取消与 UI 隔离原型

日期：2026-11-04。状态：采用；本轮搜索与固定页面隔离原型已实现。

## 搜索契约与边界

API 版本保持 `1`，握手响应可增加 `capabilities`。原有命令插件不必声明新能力，`Serve` 接口继续兼容。动态搜索插件必须同时协商 `search.query` 和 `$/cancelRequest`，并在 Manifest 中声明 `contributes.searchProviders`。

当前每个 Provider 返回完整结果批次；宿主并行执行，在各 Provider 完成后增量发布聚合结果。静态命令索引在宿主搜索，不唤醒进程。根据前缀、最小字符数筛选 Provider；每个插件最多 8 个，每次查询最多选取 32 个，每个 Provider 请求最多 20 项，聚合最多展示 100 项。

结果 ID 由插件、Provider 和局部 ID 组成；静态命令使用保留的 `$commands` 命名空间。宿主验证局部 ID、标题长度、输入长度和分数，并要求 `commandId` 属于来源插件已声明的命令。插件不能指定其他插件作为动作目标。动态分数最多为 0.8，静态命令基础分为 0.85、标题精确匹配为 1，相同评分按标题与唯一键稳定排序。当前没有使用历史排名。

Shell 发起单调递增的查询序号，宿主拒绝乱序启动；双方都检查查询 ID，取消后的结果不得覆盖新查询。搜索更新通过 `DispatchWailsEvent` 定向投递给可信 Shell，不能使用会广播到多个窗口的 `Window.EmitEvent`。

默认选择在用户未操作时跟随当前排名第一项，避免锁住最早返回的即时回声。用户通过方向键或实际鼠标移动选择后，以结果唯一键保持该项；列表增长、重排和完成不得重置仍存在的手动选择。修改查询、重新呼出或手动选中项消失时恢复自动选择。唯一键和手动选择标记使用同一函数式状态更新，处理与增量结果同批到达的方向键事件；不使用布局变化可能触发的 mouseenter。浏览器固定测试页覆盖默认跟随、首行边界手动选择、查询重置、上述竞态与回车动作。

## 运行时并发与取消

注册表互斥锁不覆盖 RPC 等待。每个插件有独立的进程与状态锁，安装、发现、卸载和关闭通过单独的变更锁串行处理。插件激活握手仍由单插件锁串行化；已经激活后的请求可并行。停止后允许下一次显式调用重新激活，卸载后旧实例不可重新激活。

SDK 同时处理最多 16 个在途请求，输出序列化；宿主传输层最多保留 64 个请求。SDK 的搜索处理器接收 `context.Context`，并在收到 `$/cancelRequest` 后取消相应请求。取消消息不带 JSON-RPC ID，参数中的 ID 指向原请求。

搜索调用预算为 2 秒；查询取消或超时后，宿主立即结束该查询的等待，并给予插件 500 ms 返回取消响应。取消通知必须在原请求写入管道后发送。插件配合取消时，进程和无关请求保留；插件不响应取消或管道阻塞时，回收整个进程，这会影响该进程中的其他请求。后续调用可重新启动插件。

命令执行维持原有 5 秒预算及错误 / 超时终止进程策略。未实现心跳、优雅 shutdown、插件侧逐条流式结果和跨插件 RPC。

## UI 隔离验证与承载决定

普通 Wails 窗口默认包含宿主机制，因此不直接加载第三方 HTML。当前采用固定测试页验证 `sandbox="allow-scripts"`、无 `allow-same-origin` 的 iframe：

- 客体拥有不透明源，不能访问父页面 DOM 或 localStorage。
- 初始文档 CSP 禁止网络连接、图片、子框架、表单和 base URL；只允许内联测试脚本与样式。
- fetch 限制探测包含正对照：父页面先确认同一 data URL 可读取，再检查客体读取被拒绝，避免仅凭无效域名或资源不存在得出隔离结论。
- 客体中没有 `_wails` 或 `__WAILS__` 宿主绑定入口，Wails 运行时及资源 fetch 均被阻止。
- 父页面通过专属 MessageChannel 与当前 frame 通信，不监听全局 postMessage 来执行宿主动作。
- 只接受结构受限的 ready 报告和 close；模拟 execute 消息被拒绝。二次加载会撤销通道并销毁客体。
- 开发原型通过 `-ui-probe` 启动，不注册全局热键和托盘；不会干扰正常实例。

**承载决定是验证方向，而非开放第三方 UI 加载。** 当前只嵌入仓库固定测试文档，尚无任意插件 HTML、资源路由或权限 API。CSP 不应被视为阻止所有自导航的保证；二次 load 销毁是事后撤销，不能保证导航请求发出前拦截。iframe 也不提供 CPU、内存及渲染进程故障隔离。

公共插件 UI 接入前，需要补齐导航前拦截或受控资源承载、资源归属校验和异常预算，并评估独立渲染进程方案。不能把本轮负向探测结果推广为原生插件沙箱或完整公共 UI 安全保证。

## 本轮验证记录

- 用户确认上一轮三屏定位、20% 纵向位置和全屏呼出正常。
- Go 真实进程测试覆盖两个独立原生 Provider 并行、协作取消保留无关命令与进程、不合作进程回收、卸载中止搜索、原有插件生命周期；竞态检查通过。
- 协调器测试覆盖快慢来源增量返回、结果命名空间、未声明动作过滤、分数约束、取消后丢弃旧结果及静态命令不激活 Provider。
- 桌面实测先出现静态命令和快来源，随后出现慢来源；动态结果的参数可带入命令并执行。
- 一次本机含冷启动 CLI 记录：静态结果约 4 ms，快来源约 386 ms，全部结果约 1356 ms。此为单次样本，尚未做 P95 验收。
- Chromium 与 macOS WKWebView 的固定页探测均报告父页面、绑定入口、存储、运行时请求、资源请求和网络请求受限，非法动作被拒绝。Chromium 另验证输入、close 及二次导航销毁；中文组词体验仍需实际输入法操作，程序填字不能替代输入法验收。

## 复现

```sh
make setup
make demo
# 搜索 demo 查看快慢来源；搜索 fail 观察部分来源失败。
# CLI 与桌面请避免同时修改同一插件目录。
./bin/sinanctl -plugins .sinan-dev/plugins search demo
./bin/sinan -ui-probe -plugins .sinan-dev/probe-plugins
```

原生隔离验证向 stdout 输出仅包含布尔值的 `ISOLATION_PROBE` 报告。使用 `npm --prefix apps/desktop/frontend run dev` 后，也可在浏览器打开 `http://127.0.0.1:9245/?isolation=1` 验证固定页面边界；浏览器模式不连接桌面搜索服务。
