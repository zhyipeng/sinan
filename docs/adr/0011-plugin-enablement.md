# ADR 0011：插件持久启用策略

- 状态：已实施
- 日期：2026-11-05

## 原因

停止进程只能暂时结束运行，下次搜索或命令会再次激活。按照后续计划，需要关闭插件功能并在重启后保持选择，同时保证管理插件自身被禁用时仍有恢复入口。

## 决策

- 核心设置增加保留命名空间 `$plugins`，`disabled` 数组保存显式禁用的合法插件 ID，最多 256 项。普通插件 ID 不能匹配此命名空间。沿用版本 1、原子替换和 revision 存储，不添加独立并发写入路径；命名空间不存在时兼容为默认启用。
- `SetPluginEnabled(id, enabled)` 在管理变更锁下串行执行，先持久化完整列表，再更新实例和停止进程；失败不改变当前进程、策略或状态。启用只回到 installed/按需激活，不立即执行插件代码。
- 插件实例保存独立 `disabled` 标志，管理快照公开此布尔值并将状态显示为 disabled。底层运行状态与停用策略分开；停止、配置保存不能清除禁用标志。
- 内核在进程激活及命令执行入口拒绝禁用插件，并在 RPC 返回后检查实例和进程身份，防止禁用前的结果复活。搜索协调器不调度禁用插件，也在发布结果时重新检查可用状态；桌面策略变更前后取消旧查询，Shell 拒绝打开已禁用视图。
- 重载、升级、回退和同 ID 重装从核心策略重建实例，保留禁用状态。禁用插件的升级/重载只检查包与可执行文件等静态条件，不运行候选握手；初始化问题可能在重新启用后的首次调用才暴露。启用仍受原生信任和文件变化检查约束。
- 管理插件 0.2.0 在已有行操作后增加启用/禁用。禁用管理插件自身时退出其视图；Shell 的独立恢复入口提供仅针对管理插件的重新启用动作。CLI 提供 `enable ID` 和 `disable ID`，仍遵守插件根目录独占锁。
- 设置文件读取失败、未知版本或启用策略格式无效时，不知道哪些插件曾被禁用，因此保留文件并阻止所有插件激活，提供诊断，拒绝策略更改。离线修复后重启恢复读取；不自动重置或覆盖用户配置。

## 边界

配置、缓存、历史、原生信任记录与包文件不因禁用而删除；卸载也保留显式禁用选择，同 ID 重装后需手动启用。此行为适用于全部插件，包括系统插件。

这只是宿主生命周期策略，不是对可信原生进程的操作系统权限撤销或安全沙箱。停止前已发生的外部动作不会回滚；应用自行启动的脱离宿主管理的进程不在此处保证范围内。已有旧版宿主不识别该策略，不保证降级运行仍保持禁用限制。插件 stdio 协议版本不变。

## 验证

- 真实子进程与 Go 竞态测试：运行中禁用终止进程和在途查询；直接执行及 Provider 入口拒绝，停止/刷新/重启后保留，重新启用后恢复按需激活。
- 禁用状态下升级和重载带有失败初始化标记的原生包不会执行代码；同 ID 重装继续禁用。并发修改不同插件不会丢失选择。
- 写入失败保留原进程和策略；启用策略/设置文件损坏时不激活插件、不覆盖文件。保留命名空间不能通过插件设置接口访问。
- 搜索测试覆盖静态命令排除、不调度禁用 Provider，以及禁用后到达的结果/失败不会重新显示。
- 浏览器通过真实 Shell、管理组件和模拟 IPC 验证切换、保存失败提示、搜索排除、导航后状态保留、禁用时重载及管理插件自身的禁用和恢复；原生持久化由 CLI/内核验证，不以浏览器模拟替代。

本机独立临时插件根目录中，真实安装应用检索与管理插件，每条 CLI 命令重新创建宿主：禁用应用检索后跨进程搜索无结果、直接执行刷新被拒绝、重载仍禁用；启用后恢复 Safari 搜索。管理插件禁用后不出现在 `plugins` 查询，CLI 启用后恢复。未用此验证改写开发实例的启用选择。
