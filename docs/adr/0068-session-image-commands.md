# ADR 0068：会话图片命令与剪贴板图片快照

- 日期：2026-11-16
- 状态：工作树实现；未发布，未实机 UI 验收

## 背景

主搜索已能按图片 inputMatcher 提供插件入口，隔离页面能通过 `readLaunch()` 获取原图资源 URL；此前原生后台无法读取同一快照。让后台重新读取系统剪贴板可能识别另一张图，把 base64 放进普通页面命令则突破 64 KiB 桥预算。用户要求 OCR 接收主搜索图片自动识别、显示原图，以及页面粘贴/复制快捷键。

## 决策

宿主提供通用图片机制，OCR 业务仍在独立官方插件。增加初始化能力 `ui.image-command.v1`、UI Bridge 2 的 `clipboard.readImage` 与 `command.executeImage`；前者受视图独立 `clipboard.read` 权限控制，后者只接受会话当前图片 URL 与已声明命令。宿主复制同一 PNG 快照到原生后端，页面不发送图片正文、不接受路径。来源包括主输入框显式传入图片和用户在页面内显式触发的系统剪贴板快照。

沿用主搜索图片验证：PNG 最多 4 MiB、16,777,216 像素并完整解码。每会话一图，成功替换后旧 URL 失效，失败保留旧图；会话撤销释放图片。既有页面调用预算、CSP、资源交付累计预算与插件实例/指纹检查不变。只有后端 `command.executeImage` 请求扩展为小于 6 MiB；SDK 将其分发到 Command 回调的可选 Image 字段，并拒绝普通命令携图、空图和超限图。

OCR 首次读取 launch 后自动识别；页面 Cmd/Ctrl+V 或 paste event 含 image 文件项时调用宿主快照接口（使用系统剪贴板适配，不使用浏览器 Blob），再把同一 URL 用于预览和识别。非图片快照返回 null，普通文本粘贴保留原行为；快捷键不依赖 WebView 是否在 paste event 提供 file items。无选区的 Cmd/Ctrl+C 复制当前编辑结果，有选区时交给原生复制；输入法组合、额外修饰键与重复按键不触发自定义复制。后台仍使用 ADR 0067 的任务租约与私有 worker 生命周期。

## 影响与兼容

插件仍为未发布的 0.1.0，须配套本轮宿主；已发布宿主 v0.2.1 不具备新能力，后台初始化明确拒绝。官方仓库 SDK 快照记录原提交和可重放的工作树补丁及摘要，不伪造新提交。注册表不登记未发布资产，未来发行必须选择真实包含新能力的最低宿主版本。

共享 Go/JS 实现适用于三端协议，系统剪贴板继续采用既有平台适配与错误语义；Linux X11/Wayland 仍取决于各自剪贴板工具/会话可用性。完整 OCR native 包仍仅本地验证 macOS arm64，其余平台限制不变。无界面测试覆盖快照隔离、替换、撤销、非法路径/资源、独立传输预算、自动识别和快捷键；这些测试不代替三端 WebView、系统粘贴事件、授权与焦点实机验收。


发行前补充：UI helper 的会话图片响应上限须为 4 MiB，普通包资源仍为 512 KiB；二者均受原有 6 MiB 私有帧和 8 MiB 累计资源交付限制。WebView2 将 `launch.image.url` / 剪贴板图片 `url` 转为该视图的私有 HTTPS origin，并仅将 `command.executeImage.input` 转回内部 URL；重编码前严格拒绝重复和额外字段，用户文本/存储值不改写。v0.3.0 发行已取消，最低完整宿主选为 v0.3.1，保留旧标签且不发布旧资产。
