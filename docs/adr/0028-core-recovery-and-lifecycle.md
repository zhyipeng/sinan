# ADR 0028：退出等待、系统插件修复和主面板切换

日期：2026-11-09。状态：已实施。

## 原因

核心能力检查发现三项可复现缺陷：后代继承 stderr 导致 Stop 无限等待；受保护系统插件清单损坏后无法通过普通安装/升级恢复；HTML 候选页启动失败会撤销原页面。

## 决策

- 后端和 UI 客体的 stderr 直接接到系统空设备，避免 os/exec 为 io.Discard 创建复制管道；另设置 500 ms WaitDelay。继续监督和终止直接进程。本改动不承诺终止任意后代，也不构成系统安全沙箱。
- 新增专用 PreviewSystemRepair / RepairSystemPlugin，仅接受 system.settings、system.plugin-manager 的声明式包，以及对应的单一 open/settings、open/manager 可信组件声明。普通 ApplyPackage 的变更保护不变，系统插件仍禁止禁用、卸载。
- 修复预览同时记录候选包和实际已安装目录的内容指纹；已安装清单不必可解析。目录缺失走原有原子安装，目录存在则复制候选、复验双方指纹、记录事务、备份原目录、替换并提交。替换失败回滚；回滚失败保留日志和备份并阻止继续变更，启动时复用升级恢复机制。原实例撤销后不执行损坏包。配置、历史及包外数据不随包目录替换。
- 修复不绕过符号链接、体积和文件数量限制；无法安全读取的损坏目录仍需人工处理。它不是签名校验或自动下载恢复。
- Shell 恢复表单使用专用接口，支持修复设置或插件管理；CLI 提供 repair-system 目录。接口只由可信宿主调用，不开放给 HTML 页面桥。
- HTML 新页面准备和握手成功后才提交主面板替换并撤销前一会话；失败保留原会话，在候选启动影响焦点时尝试重新聚焦原面板。并发候选提交时撤销的是当时的附着面板，独立窗口不参与替换。

## 验证

新增后代继承 stderr 的后端 Stop、请求超时及 UI 客体 Stop 回归；新增系统插件清单损坏在运行中/重启后恢复、双方文件变化拒绝、包类型限制、保护策略及失败回滚后启动恢复回归；新增 HTML 资源缺失、握手失败保留原页和成功切换撤销旧页回归。原生交互与浏览器夹具的验证结果记录在核心检查文档。

后端协议和 UI 桥版本不变。独立进程仍只代表故障隔离。
