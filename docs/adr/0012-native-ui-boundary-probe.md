# ADR 0012：无 Wails Bridge 的原生 UI 边界验证

- 状态：开发验证已实施；公共插件 UI 尚未开放
- 日期：2026-11-05

后续 [ADR 0013](0013-ui-session-revocation.md) 已将原生开发宿主接入内核会话，改为在临时目录安装固定夹具、逐次读取会话资源，并增加禁用撤销模式。下文保留本记录初次交付的验证过程。

## 原因及源码核实

ADR 0003 的固定 iframe 验证了不透明源与逻辑桥接边界，但二次加载后销毁不能保证导航请求发出前拦截。公开加载第三方资源前，必须补足资源归属、导航和桥接撤销的证据。

针对锁定的 Wails v3.0.0，本机模块源码 `pkg/application/webview_window_darwin.m` 实现了导航开始、提交、完成通知，没有 `decidePolicyForNavigationAction` 可取消决策；Go 层注册这些通知不能替代导航前控制。不能直接用普通 Wails 窗口加载第三方文档，也不通过替换其内部 delegate 破坏原有窗口机制。

## 决策

### 资源快照

`internal/plugin/uiview` 构建独立于页面运行的只读快照。调用者必须提供已确定归属的 UI 根目录，不能传入整个插件包或其他插件目录。开发宿主只用内嵌固定测试资源；目录加载接口尚未暴露给 Wails、CLI 或 manifest。

- 归属 ID 沿用合法插件 ID，入口必须为规范的相对 `.html` 路径。
- 目录用 `os.Root` 限制文件访问，拒绝符号链接根目录、符号链接条目及非普通文件。
- 首版最多 128 项（含目录）、单文件 512 KiB、总字节 2 MiB、路径 256 字符和 8 层分隔；路径只接受 ASCII 字母、数字、下划线、横线、点与斜杠。
- 只接受 HTML、JS、CSS、PNG、JPEG、WebP；不允许额外配置、源映射、字体或任意文件类型。后续扩展需重新评估格式和预算。
- 读取完成后不再访问原目录，返回资源字节也不共享可变切片；源文件移除或替换不改变已建立的快照。
- URL 只能指向 `sinan-plugin://<owner>/<path>` 已存在的资源，拒绝其他归属、非规范路径、编码别名、查询和片段等。快照导出包含资源字节，禁止将其内容写入日志。

### 原生开发宿主

新增 `apps/ui-probe`，通过 `make ui-probe` 启动正常与消息洪泛两个短生命周期进程。它不是安装到开发实例的 demo 插件，不读取插件根目录、不注册热键，也不加载宿主绑定。

- 新建 WKWebView 配置，使用非持久数据存储，只注册 `sinan-plugin` 资源处理器和开发验证专用的 `sinan` 消息处理器。没有 Wails 运行时、绑定或宿主 API 分发。
- 资源处理器只按精确 URL 读取内存快照，响应携带 CSP、nosniff 和 no-store；不提供文件路径或其他插件资源路由。
- CSP 禁止网络连接、表单、框架、Worker、媒体、对象及 base URL；脚本、样式与图片只能走受控 Scheme。该快照不是内容清洗器，客体 JavaScript 仍会运行。
- 原生 `WKNavigationDelegate` 仅允许宿主发起的首个、精确匹配入口的主文档导航。其他主框架、子框架、新窗口和重新导航在决策阶段取消；`WKUIDelegate` 新窗口创建也返回 nil。
- 开发桥接只接受主框架、原入口文档的消息。ready 必须单次、版本和字段精确；报告只接受固定布尔字段；close 只允许单独 kind。未知或多余字段被拒绝，没有 execute 等动作。
- 消息 JSON 校验预算为 4 KiB，每个宿主会话最多 32 条，超过后移除消息处理器并结束验证。验证主循环最多等待 8 秒，渲染进程终止或加载失败同样结束；关闭时移除通道及 delegate。

### 存储和进程边界

实测独立自定义 Scheme 文档能访问自己的 localStorage，所以它与旧 iframe 的 `storageBlocked` 含义不同。这里验证新会话存储初始为空，刻意留下标记，下一次进程使用新的非持久存储时仍为空，并检查原生存储对象不是 persistent。允许客体使用自己的临时状态，不应宣称其完全不能访问存储。

不使用 `WKProcessPool` 作为专用渲染进程证据：本机 SDK 明确标注 macOS 12 起创建多个 Pool 已无效果。当前验证程序与日常 Wails 宿主是不同进程，但没有证明 WebKit 提供每插件独占 renderer，也没有实现 CPU、内存或原生权限沙箱。

## 实测

本机 macOS 26.6 / arm64 运行 `make ui-probe`：

- 正常模式 ready、无绑定、临时存储、归属内图片正对照、跨插件资源拒绝、导航拒绝、网络拒绝、非法消息拒绝及 close 均通过，`budgetRevoked=false`，退出 0。
- 洪泛模式先通过同样的边界检查，再发送 64 条无效消息。处理预算耗尽后 `budgetRevoked=true`，后续 close 未接受（`closeReceived=false`），按预期退出 0。
- Go 宿主先访问同一个本地 HTTP 服务作为可达性正对照；客体 fetch、主文档导航和新窗口尝试都指向该服务的逃逸端点。两个模式中正对照成功，逃逸端点请求数均为 0，不以无效域名或事后销毁冒充导航前拦截。
- Go 单元与竞态测试覆盖资源归属、URL 规范、目录/入口符号链接、源变动后的快照不变、数量/单文件/总量预算及取消。无 cgo 构建走不支持分支，不声称已验证其他平台 WebView。

## 后续接入条件

此轮不增加 manifest UI 声明，不向正常 Shell 注入安装包的 HTML，不提供公共数据、文件、命令执行或网络桥接。原生代码目前只运行固定探测页，不能据此接受任意恶意页面。

公开接入前，需要设计会话绑定包指纹及启用状态、升级/禁用/卸载撤销、客体进程启动与回收、权限默认拒绝（含系统弹窗）、异常与资源耗尽处理、可用性及跨平台实现。4 KiB 检查发生在 WebKit 反序列化之后，不是严格内存配额；8 秒验证期限也不是任意 JavaScript 的安全执行预算。完整任意页面承载必须继续受这些条件约束。
