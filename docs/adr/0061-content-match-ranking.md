# ADR 0061：可降低的内容匹配分数

日期：2026-11-14。状态：已实现，验证记录见下文；真实 UI 未验收。

## 背景与决策

翻译插件用通用非空文本规则提供内容入口，原有固定 0.95 分高于动态应用 Provider 的 0.8 上限，导致普通应用查询经常先显示翻译。不能在内核按插件 ID 写业务特例；改为可选的通用清单字段 `commands[].inputMatchScore`，由插件表达宽泛匹配的低优先级。

字段为 0～0.95 的有限数值，仅在同一命令存在非空 `inputMatchers` 时合法；省略保持既有 0.95，显式 0 不等同于省略。同步 Go 清单校验、JSON Schema 和生成的桌面类型。

普通搜索在仅内容命中时采用该分数；名称、关键词或拼音同时命中时至少保持 0.85，精确标题仍为 1。原文仍通过既有打开参数传入，不更改输入长度、匹配预算或本地匹配语义。使用历史仍沿用既有最多 0.025 的加分，因此该分数不是「永远最后」的固定位置声明。

粘贴内容搜索采用同一分数，先按分数降序，再按标题与结果键排序；过去默认分数相同时的次序不变。粘贴时不套用名称优先，因为其筛选只作用于内容入口。

官方翻译插件 0.1.3 将该分数设为 0.2；原有精确结构匹配工具默认分数不变。

## 兼容性与仓库影响

这是 API 1 清单的增量字段；旧宿主严格拒绝未知字段，插件包需要支持本 ADR 的新版宿主，不能仅凭同为开发版本号视为兼容。后端 RPC、UI 桥、权限和隔离边界不变。SDK 快照没有命令清单结构，本轮不更新其来源或哈希。

已核对 `sinan`、`sinan-official-plugins`、`sinan-plugin-registry`：前两者分别实现机制与配置，目录尚无翻译插件的正式发布记录，本轮不新增未发布资产。正式登记时需明确宿主具有本字段，使用真实版本与资产。

## 验证边界

无界面测试覆盖分数边界、非法/非有限值、缺少匹配规则、默认分数、显式零分、应用优先、名称/关键词优先、特定 JSON 匹配优先、粘贴排序及原文保留。共享逻辑不增加系统调用，macOS/Windows/Linux 复用同一实现；跨目标编译不代表目标平台运行或原生 UI 验收。

本轮本机验证：完整 `node scripts/desktop.mjs test`、官方插件 `npm test`、搜索与清单包静态检查、macOS arm64 桌面无界面构建均通过；搜索包测试可执行文件及翻译插件分别完成六个 OS/架构交叉构建，插件包入口与 SHA-256 生成通过。临时插件目录经当前 CLI 检查和安装，确认应用结果高于翻译 0.2、精确搜索翻译得分为 1。未操作日常安装目录，未运行真实桌面或原生 WebView，也未在 Windows/Linux 执行测试二进制。
