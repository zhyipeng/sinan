# ADR 0065：插件独立版本与发布标签

日期：2026-11-16。状态：已采纳。

## 问题

官方插件共用源码仓库，Git 标签在仓库内唯一。商店与登记校验器原先强制 `tag == v + version`，导致无关插件不能同时发布 0.1.0；日历因此临时从 0.1.2 首发。版本应属于插件身份，而非整个官方插件仓库。

## 决策

- 新发布优先使用 `<plugin-id>-v<version>`，例如 `tools.calendar-v0.1.0`；历史 `v<version>` 保持有效。严格绑定清单/记录的 ID 和三段正式版本，不接受任意标签、其他插件 ID、版本不一致、预发布后缀或路径。
- 同仓库不同插件可以使用相同版本；同一插件仍只能登记一次同版本，发布资产保持不可变。
- 不新增目录字段，不改变 schemaVersion、API、桥、SDK、权限或包名。downloadUrl 继续精确对应仓库、标签与文件名，安装继续使用固定 Asset ID、大小及 SHA-256。
- 宿主商店、登记校验器、脚手架打包/发布校验同步更新。脚手架版本升到 4，工作流接受新旧标签，真正发布前仍校验清单。官方仓库提供从实际清单生成标签的 Node 命令，避免手工遗漏插件标识。
- 桌面应用自己的 `v<version>` 发布流程保持原样。现有插件发行、标签及登记记录不改写，日历不从已上架 0.1.2 降级；后续插件不再为其他插件跳号。

## 兼容与部署

旧宿主不接受新标签，遇到新记录可能拒绝整个联网目录并回退缓存，因此先部署包含此变更的宿主，再登记新格式资产。校验器更新和文档本身不意味着旧安装已经升级。本次只扩展接受范围，不将历史目录迁移为新格式，不创建伪发行记录。

实现使用平台无关 Go/Python/Node 字符串与元数据校验，适用于 macOS、Windows、Linux 的 arm64/amd64；没有新增原生依赖或 UI。验证覆盖同仓库同版本不同插件、新旧格式、ID/版本不匹配、路径与 URL 绑定、同插件重复版本，以及生成项目的实际打包与发布前校验；不访问真实桌面，不运行插件提交者代码。

本轮验证：完整无界面回归 `node scripts/desktop.mjs test`、商店/脚手架竞态测试与 `go vet`、macOS arm64 宿主构建通过；官方插件 46 项 Node 测试及既有 Python/Go 检查通过，登记仓库 4 项元数据测试和实际目录校验通过。商店及脚手架测试程序完成 darwin/windows/linux × arm64/amd64 交叉编译；Windows/Linux 测试程序未在目标系统运行。本次不启动桌面或浏览器，也不修改线上发行与插件版本记录。
