# ADR 0016：原生 UI 故障与响应预算验证

- 状态：固定开发客体已实施；日常桌面承载与资源硬配额待实现
- 日期：2026-11-05
- 后续：[ADR 0017](0017-desktop-plugin-windows.md) 已提供默认关闭的桌面开发入口和普通客体；本文未接入桌面的描述为当时阶段记录。

## 原因

ADR 0014 监督客体进程，但 WKWebView 的 JavaScript 可卡死而原生进程仍存活。只等待页面 close 或进程退出不能及时发现此类故障，也需要防止把正常的异步等待误判为卡死。

## 决策

- 原生开发客体记录固定故障类别：调用脚本错误、WebKit 渲染退出、导航失败、页面无响应和总期限结束。进入故障时立即撤销会话、结束本次运行并清理窗口，不回显 NSError、页面脚本或资源内容。
- ready 后由原生层调用固定 JavaScript 表达式 `true` 检查引擎能否继续执行，不接受页面自报存活。最多一个待完成检查；完成后至少间隔 250 ms 再次检查，超过 1 秒仍未完成则判定无响应。计时使用系统单调时钟，检测在原生运行循环中进行。
- 总期限仍为 8 秒；父监督器的 12 秒运行期限、撤销宽限和强制回收继续作为原生线程也挂起时的后备。这里的数值是开发验证预算，不是公开插件窗口的产品策略。
- 故障作为可信原生程序的固定诊断报告返回。管道正常完成并不表示页面运行成功，父验证程序按预期的故障类别及会话撤销、独立 PID、完成回收等条件验收。未知故障编号不得当作成功。
- 固定 failure 视图复用已声明的入口，由父进程在临时资源中选择脚本抛错、同步死循环或异步等待三种模式，不开放任意脚本注入参数或新的页面 Host API。普通 UI 的 ready/close 协议不变。
- 脚本错误或卡死后，在同一内核中创建新的正常客体并检查完整资源/桥接探测，确认故障没有使内核或后续窗口不可用。

## 验证

`make ui-probe` 增加三种实际 WKWebView 模式，连同原来的正常关闭、洪泛和禁用共六种，均在本机通过：

- `-fault script`：入口调用同步抛错，返回 script-error，撤销会话并回收；随后正常客体成功。
- `-fault hang`：JavaScript 同步死循环，返回 unresponsive，撤销并回收；随后正常客体成功。
- `-fault slow`：异步等待 1.4 秒，期间成功完成响应检查，正常 close，不触发 1 秒无响应误判。

故障夹具尚未执行完整资源/导航测试时，对应布尔值可为 false；故障模式必须匹配指定故障和全部父进程条件，不能作为正常模式验收。随后正常客体仍须通过完整检查。

## 限制

实际注入并验证的是同步调用错误和 JavaScript 卡死；渲染退出、导航失败已接入公开 delegate 回调，但尚未通过杀死真实 WebKit 渲染进程做故障注入，不能声称覆盖了全部崩溃情形。页面自身任意未捕获异常或 Promise 拒绝不一定使固定调用失败；响应检测衡量能否执行，不衡量业务正确性。

现有消息、资源、管道和时间预算不等于 CPU、内存或进程树硬配额。关闭 WebView 和回收客体的检查不证明 WebKit 辅助进程具有独立的强制治理能力，也没有实现操作系统安全沙箱。第三方任意 HTML 的日常桌面加载入口仍待接入。
