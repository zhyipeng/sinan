# ADR 0053：原生插件 UI 的共用边界与平台 Shell 适配

日期：2026-11-13。状态：共用边界及 Shell 适配已实施，Windows/Linux 原生 UI renderer 仍待实现。

## 决策与原因

用户要求继续同步适配并自行提交代码。Wails 的可信主 WebView 不作为第三方 UI 的跨平台降级方案。先将各原生 renderer 必须执行的 Go 会话边界统一，避免未来 WebView2/WebKitGTK 分别复制校验逻辑；现有 macOS renderer 立即使用该边界。

## 实施

- `nativeBridge` 固定绑定宿主持有的会话和入口，不接受页面提供插件身份。由原生导航事件传入实际目标和主 frame 标识，仅允许一次精确匹配的初始导航。
- 资源只接受 GET，继续由会话解析精确归属与路径；HTTP 方法、非主 frame、来源不匹配及超限调用均不能到达后端。页面消息的来源和 frame 必须由原生事件获取，不读取页面自报字段。
- 原嵌入适配器的 256 次请求、8 MiB 资源累计预算迁入共用边界，失败请求同样计数；消息与调用仍保留会话原有的大小、数量、并发及超时约束。撤销后不投递迟到的调用结果。
- macOS 的原生事件/C 回调传入来源、frame 与方法，并复用共用校验；配置、独立存储、CSP 和无 Wails Bridge 规则不变。普通同窗口承载及 helper 均接入，保留原生层的校验作为防御。
- 宿主按实际编译适配器的能力常量初始化承载，不再用操作系统名称推断支持。未实现的 renderer 保持默认拒绝。
- Windows 按 HMONITOR 获取光标屏幕身份，工作区通过 Wails 转换到逻辑坐标；系统主题读取 Windows 应用主题偏好，原生窗口使用现有 Wails Win32 主题适配。
- Linux GTK3 在 UI 线程查询 X11 光标屏幕与 GDK 逻辑工作区；Wayland 返回不支持，由现有显示器回退路径处理。主题读取 GNOME GSettings，应用内同步 GTK 深色偏好并观察系统设置，不改写用户桌面配置；未安装对应 Schema 时安全回退。
- 托盘仅在 macOS 使用模板图标，Windows/Linux 使用应用彩色 PNG。

## 验证与限制

共用边界的无窗口竞态测试覆盖并发导航只允许一次、来源与子 frame 拒绝、资源方法/URL 限制、失败流量预算及撤销后的迟到结果。平台编译、现有回归和真实 UI 验收分别记录。

增加不依赖 POSIX 脚本的原生进程集成测试，在含空格的目录中构建目标平台可执行文件，经过真实入口检查、精简环境、stdio 握手、中文命令往返与停止；纳入 Windows 构建矩阵，并运行共用 UI 边界测试。

这不是 WebView2/WebKitGTK 原生 renderer 的实现；Windows/Linux HTML 插件 UI 保持明确不支持，不修改默认能力开关。Windows 混合 DPI、Linux 桌面差异、系统主题动态通知和实际窗口体验需要对应平台验收；Wayland 的定位、全局快捷键及激活仍受 compositor 能力限制。没有新增沙箱保证或页面桥权限。
