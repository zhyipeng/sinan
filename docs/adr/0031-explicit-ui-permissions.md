# ADR 0031：显式、包内容绑定的 UI 能力授权

日期：2026-11-09。状态：已实施；交互 UI 验证待用户明确要求后执行。

## 原因

桥 2 的命令白名单和 storage 声明此前直接允许能力调用，缺少用户授权状态。用户确认本轮在插件管理中逐项允许/撤销 UI 命令及私有数据访问，包内容变化后重新确认。

## 决策

- 清单只描述可申请能力，不直接授予。桥 2 的每个“视图 / 命令”和“视图 / 私有数据”分别授权，默认全部拒绝。未授权也可加载固定 HTML，但实际调用失败，不执行后端或访问文档。JSON 工具首次使用需先在插件管理授权；不自动迁移或授予旧安装包。
- UI 留在可信 system.plugin-manager 0.6.0，新增折叠的 UI 权限区。可单项勾选、全部取消勾选，再显式保存。显示未授权、待保存、包更新、文件变更及保存错误；清单/后端 API 不接受额外未声明权限。
- 权限保存在保留的 `$ui-permissions` 核心命名空间，普通插件设置 API 不可访问。每个插件记录已确认包内容指纹与能力 ID，整个命名空间使用 revision 防止多个管理窗口覆盖更改；原子保存成功才改变内存授权。
- 权限检查在会话归属、声明白名单、包完整性检查之外执行，不能取代它们。代码/资源/清单任一字节变化导致指纹不同，新包不继承旧授权。恢复完全相同的已确认包字节可继续使用原授权；重装/回退不复活旧 Session。授权记录随核心配置保留，卸载不自动删除；仅匹配当前已安装包时适用。
- 任何实际授权变更均撤销该插件旧 HTML 会话，新页面重新打开后生效；没有变化的保存不撤销 HTML 会话。在途命令由撤销取消，已发生的后端副作用无法回滚，沿用强制取消可能终止插件后端的行为。
- 存储授权撤销不删除私有数据；私有数据清理也不重置权限配置。其他插件会话与授权保持。拒绝旧包指纹、过期 revision、重复/未声明能力。记录无效时 UI 能力默认拒绝，显示错误，不覆盖原记录；保存失败保留原授权和会话。
- 每命名空间最多 256 个插件记录，单插件最多 68 个声明能力（4 视图 × 每视图 16 命令及 storage）；仍受核心配置文件体积限制。未知能力类型默认拒绝。

## 接口

可信 Shell 新增 UIPermissions() 和 SaveUIPermissions(id, fingerprint, revision, capabilities)。状态包含声明能力、是否允许、是否已确认及包更新标记。能力 ID 为 `view/command/commandId` 或 `view/storage`，不接受其他插件 ID、任意 RPC 方法或系统资源路径。

CLI 增加 ui-permissions、set-ui-permissions ID 包指纹 revision JSON数组。需先退出持有同目录独占锁的宿主；显式传递已查看的指纹、修订与能力列表，没有 force 或自动全授权入口。

页面桥不提供权限管理、申请自动批准或跨插件授权能力。桥 1 仍只有 ready / close，可信设置和管理组件不依赖此权限，确保恢复入口可用。后端 RPC API 1 和 UI 桥版本不变；旧桥 2 应用在新宿主上首次需要显式授权，SDK 的 Promise 会收到未授权错误。

## 边界

这是 UI 窄桥能力授权，不是通用系统授权器或 OS 安全沙箱。原生插件仍按安装信任以当前用户权限运行，可拥有不受本策略限制的系统访问；UI 文案保留此区别。文件、网络、剪贴板等 Host API 尚未开放。损坏权限记录的应用内重置、卸载残留授权记录清理及通用权限扩展仍待后续实现。

## 验证

本轮只运行不弹窗、不抢焦点的检查。Go -race 回归覆盖默认拒绝、部分授权、撤销、在途取消、跨插件隔离、保留数据、重启持久化、新包失效、过期审查、重复/未声明能力、损坏记录拒绝且不覆盖、写入失败保留状态。现有 UI 调用测试改为显式授予测试夹具能力；原生 UI 测试夹具同步适配，但未执行。前端 TypeScript、构建、静态检查及临时 CLI 验证按交付记录执行。
