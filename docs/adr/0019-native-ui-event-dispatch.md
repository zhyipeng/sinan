# ADR 0019：客体窗口的 AppKit 事件派发

- 状态：已修复，新增原生回归通过
- 日期：2026-11-05

## 问题

用户点测发现窗口显示后约两秒黑屏、无法操作。客体在手工运行循环中仅调用 NSRunLoop，WebKit IPC 和页面定时器可以运行，AppKit 的窗口、鼠标与键盘事件却没有取出并派发。此前仅依赖脚本返回和协议关闭的测试因此不能证明窗口可操作。

## 决策

保留手工循环及撤销/响应检查，改用 NSApplication nextEventMatchingMask 取出事件，通过 sendEvent 派发，并调用 updateWindows。每次循环使用局部 autoreleasepool，避免长时间开窗积累自动释放对象。

向当前客体自身队列投递一个固定、无害的 ApplicationDefined 标记事件；报告只有在取出且调用 sendEvent 后才标记 eventLoopResponsive。该诊断不增加页面消息、权限或可配置脚本；普通页面和探测程序使用相同事件循环。

## 验证与影响

六种原生探测和普通客体事件队列回归通过。在临时源码副本恢复旧的 NSRunLoop 循环，新断言失败；当前实现通过。此前超过八秒的脚本存活检查仍保留，但不再作为窗口可操作的充分依据。

原生测试在 TestMain 中调用外部 go build，Go 测试缓存不会自动追踪所有外部客体源码；运行原生检查时使用 -count=1，避免复用过期结果。现有权限、导航、CSP、会话撤销和后台进程协议不变。

真实鼠标、键盘、中文输入法和标题栏关闭仍按手动验收步骤检查。更新可执行文件不会替换正在运行的旧客体，复测前应退出旧验收实例并重新启动。
