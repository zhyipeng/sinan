# ADR 0050：安装与更新直接衔接检查和应用

- 状态：已实施；真实 UI 未验收
- 日期：2026-11-13

## 原因

用户要求去掉安装、更新插件时的二次确认。原有可信界面先检查，再要求点击确认，增加重复操作。

## 决策

- 商店卡片、详情页和本地目录 / ZIP 安装均在用户点击后自动检查，声明式和纯前端包校验通过后立即应用，不增加普通版本确认步骤。同内容只提示，不重复应用。
- 原生包不自动授予信任，保留单个明确标注的「信任并安装 / 信任并更新」动作，替代原有勾选后再确认的组合。此授权仍绑定当前检查候选，更新原生包不会按插件 ID 自动继承信任。
- 商店继续分别调用 Prepare 和 Apply；后台单次票据、目录修订检查、应用前资产撤回检查、摘要与大小校验、包内容及已安装内容指纹、升级回退均保持。不将取消界面确认等同于跳过服务端核验。
- 原生信任候选可取消，离开界面时仍清理待处理商店票据；已明确授权且发出的应用操作继续执行并同步命令快照。检查完成前已卸载的界面不发起自动安装。
- 不修改后端或 SDK 协议，不调整系统插件保护、开发链接信任、系统修复与数据清理确认流程。

## 验证

运行无界面前端构建、商店与内核测试及竞态检查，沿用原生信任、源包变更、目录撤回、票据失效和已安装包基线变化的回归。更新人工浏览器回归脚本的授权入口，按项目约定不运行真实桌面或浏览器验收。
