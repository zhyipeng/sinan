# ADR 0010：本地插件管理可信组件

- 状态：已实施
- 日期：2026-11-05

## 原因

安装升级、停止、卸载和重载机制已经建立，但管理界面仍直接写在 Shell 中。本轮按照架构与后续计划，将日常管理界面放入系统插件，保留宿主恢复能力。

## 决策

- 新增声明式 `system.plugin-manager` 0.1.0，通过 `open` 命令和 `manager` 视图声明入口。搜索“插件管理”或 `plugins`、点击 Shell 的 `···` 均进入同一插件视图。开发准备脚本在既有插件之后准备此插件。
- 插件组件拥有列表、状态标签、安装目录、包预览、信任勾选、操作进度和错误提示。组件不导入宿主绑定，通过静态类型化适配器调用既有管理机制；任何安装包都不能借此在 Shell 注入代码。
- 与设置组件一样，管理组件随宿主构建。只有 `system.plugin-manager/manager` 注册键映射此可信组件，不按 manifest 路径导入 JS/HTML。适配器不属于第三方 API 或权限授权，不改变插件线协议。
- 宿主仍负责信任记录、指纹检查、升级回退、并发与生命周期。组件变更插件后同步 Shell 的命令快照，晚到的操作结果不写入已经卸载的视图。离开页面不撤销已发出的内核操作。
- 允许卸载管理插件自身，完成后退出组件并进入独立恢复入口。缺失管理插件时，`···` 同样打开恢复入口。宿主恢复入口只检查状态和恢复本地声明式 `system.plugin-manager` 包，沿用先检查、再按指纹应用的流程，不承担日常插件列表业务。
- Shell 为可信视图设置 React 错误边界：同步渲染失败后显示固定提示，提供恢复按钮，返回搜索仍由宿主控制。组件自己的异步请求单独处理错误。此边界不等同于进程隔离或第三方 UI 安全沙箱。

## 限制

本记录交付时未实现永久启用/禁用，后续已由 [ADR 0011](0011-plugin-enablement.md) 补齐。签名、市场或远程更新仍未实现。停止进程仍可被下一次搜索重新激活，不应称为“禁用”。

恢复包能恢复缺失的管理清单和正常已注册包，不能修复编译进宿主的组件代码，也不保证离线损坏且无法注册的目录能自动恢复；这些情况需重新构建或离线修复。恢复入口不接受原生管理包。模块加载/整个 WebView 或宿主进程失败不属于 React 错误边界能力。

## 验证

沿用真实内核的既有安装、信任、升级回退、重载、并发及竞态测试。浏览器通过真实 Shell 与模拟 IPC 验证管理搜索入口、窄桥接操作、包变化拒绝、原生信任要求、停止卸载、卸载自身后恢复、缺失时的恢复入口，以及组件同步渲染故障后恢复入口仍可用。开发实例安装与静态命令检索另行验证，不将浏览器模拟视为原生窗口实测。
