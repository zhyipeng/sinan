# ADR 0066：宿主共享系统剪贴板 API

状态：已实现源码与无界面验证；未发布，真实系统剪贴板与 UI 未验收。

## 决策与原因

计算和剪贴板插件原来分别实现平台剪贴板调用。按用户要求，将系统文本/PNG 读写集中在 `internal/clipboard`，保留插件内的计算、历史、轮询、去重和持久化业务。宿主不主动监控、不持久化剪贴板，也不写入日志。

原生插件通过已有 stdio 通道反向发出 JSON-RPC 2.0 请求；双向请求 ID 各自独立，接收循环根据 method 区分请求与响应，避免后端命令等待宿主时死锁。初始化增加可选 `hostCapabilities: ["clipboard.v1"]`；官方计算/剪贴板 0.2.0 在缺少该能力时拒绝初始化，不能仅凭 API 1 或相同开发版本判断兼容。

宿主仅接受 `clipboard.read` / `clipboard.write`，权限取自启动时捕获的清单，不接受请求中的插件身份。最多四个并发反向调用，重复在途 ID 或超量请求终止进程；每次调用预算两秒，进程结束取消排队。所有插件共享串行平台访问；取消在进入平台操作前检查，已开始的同步系统调用不能保证强制撤销。

数据为 `{kind:"text"|"image",data:<base64>}`，图片仅支持 PNG。保留文本 256 KiB、PNG 8 MiB / 1600 万像素限制。普通 RPC 继续限制 1 MiB；仅反向 clipboard.write 请求和 clipboard.read 响应使用 12 MiB 帧预算，以容纳 base64。传输扫描器因此最多缓冲 12 MiB；不允许普通插件命令借此扩大结果预算。

UI Bridge 2 增加独立视图权限 `clipboard.read` / `clipboard.write`，与原生顶层权限互不继承。页面 SDK 提供 `readClipboardText` / `writeClipboardText`，文本最多 32 KiB；继续复用 64 KiB 请求、192 KiB 响应、500 毫秒和会话撤销边界。JSON 转义导致超过原桥预算时仍拒绝。图片读写由后端 API 提供，不扩大页面桥，不注入 Wails Bridge。

## 平台与兼容影响

macOS 的 Cocoa（需要 CGO）、Windows 的 Win32 Unicode/PNG/DIB、Linux 的 X11 xclip / Wayland wl-clipboard 适配从官方剪贴板插件迁至宿主，连同无界面位图与依赖测试迁移。macOS 继续跳过 Concealed/Transient/AutoGenerated 类型；Linux 缺少会话或工具明确报错，Wayland 不静默走 X11。不支持的宿主构建明确返回不可用。序列号是平台优化：macOS/Windows 未变化时返回空内容；Linux 可能重复返回内容，调用方负责去重。

官方计算、剪贴板均升级为尚未发布的 0.2.0，后端改为纯 Go SDK 调用，不再持有系统剪贴板适配；剪贴板插件可在任一平台交叉构建六目标。旧插件保持原行为，新插件要求新宿主。SDK 快照同步协议、Go SDK、页面 SDK，并在 UPSTREAM.json 标注基线提交、working-tree 来源和各文件哈希。正式提交后可将来源更新到最终提交。

登记仓库协议格式无需变更；没有生成或登记新发行资产，也不修改已发布包和摘要。原生信任确认依旧需要，清单能力检查只约束 Host API，不是操作系统沙箱，也不阻止原生插件自行调用系统。

## 验证边界

回归使用模拟内容和管道，不访问真实剪贴板、不打开桌面、WebView 或浏览器。覆盖权限拒绝、请求形状、大图片双向传输、错误后普通请求继续工作、文本/图片预算、位图转换以及取消前拒绝访问。Windows CI 纳入无窗口剪贴板校验与权限用例，原生 stdio 用例沿用三平台构建矩阵；CI 配置不等于远端已运行。构建与执行结果见跨平台文档，实机系统剪贴板及 UI 验收仍待明确安排。
