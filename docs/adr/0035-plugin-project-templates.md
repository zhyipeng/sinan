# ADR 0035：插件开发模板与创建入口

日期：2026-11-11。状态：已实施，无界面检查通过；真实 UI 未验收。

## 决策

用户要求在插件管理新增“创建插件”，填写名称、选择目录应用模板，并确认同时提供 Go 后端 + HTML、纯 HTML 两种模板。

管理插件提供表单与 `scaffold` Go 包，后者内嵌模板并负责生成独立项目。宿主增加仅供可信 Wails 页面的 `ChoosePluginDirectory(context)` 与 `CreatePluginProject(options)`；不进入第三方 UI 桥或 stdio 协议，也不引入通用任意文件写入 API。选择对话框绑定真实调用窗口，主面板在对话框期间暂停失焦隐藏与快捷键重置，不影响独立窗口策略。

公开 SDK/协议包内嵌最小源码并通过开发辅助函数返回副本，用于创建可独立构建的项目，不引入新 Go 模块边界或宿主 internal 依赖。创建来源和 SDK 摘要记录在模板元数据中，不代表签名。模板 v1 不改变现有后端 API 1、UI 桥 2、私有数据限制、原生安装信任或暂缓权限系统的决定。

## 行为与限制

- 父目录由用户选择；在其下使用插件 ID 创建新目录。名称 JSON 编码，ID 严格校验且不允许 system 命名空间。
- 拒绝已有目录或符号链接，固定模板文件采用根目录约束和排他创建，不覆盖用户项目。
- 写入失败保留未完成目录并报错，不自动递归删除未知内容。不防御当前用户任意进程的文件篡改。
- 生成模板只写源码，不执行构建、下载、安装或 Git 初始化，也不注册官方身份。
- 两种模板均提供主题 CSS 变量和私有草稿；Go 模板包含 echo 命令及最小 SDK 快照；纯 HTML 模板不生成 Go 模块或后端。
- 构建使用无 npm 依赖的 Node 脚本，产物为 dist/plugin；Go 后端支持按 GOOS 设置 Windows .exe 入口，不据此声称跨平台 UI 已验证。
- 插件管理版本从 0.5.0 增至 0.6.0，可信组件仍随宿主构建，开发实例通过原有准备脚本更新清单。

## 验证

- `make test` 通过：前端类型检查/构建、主题 SDK 测试和全量 Go 竞态检查。
- `go vet ./...` 与 `make build` 通过，生成桌面宿主、CLI 和 UI helper。
- 两种模板在带中文及空格的临时父目录中生成后，经真实 Node 构建脚本独立构建，并安装到临时宿主目录；Go 示例实际握手和 echo 调用通过，两者均成功准备隔离 UI 会话，未打开窗口。
- 拒绝非法 ID、system 命名空间、非法模板、超长/控制字符名称及相对父目录，错误请求不落盘；已有项目文件与同名符号链接保持不变。
- 主面板原生对话框的嵌套计数、失焦抑制与关闭恢复策略单元测试通过。
- 最后对模板生成器的格式化/校验调整执行定向竞态回归通过；`git diff --check` 通过。
- 未启动桌面、原生目录框、WebView 或浏览器交互回归；目录框附着与交互仍待用户明确要求时验收。

## 后续补充：安装目录选择

2026-11-11：按用户要求，现有安装 / 升级输入框旁新增“选择目录”，保留手动输入。`ChooseInstallDirectory(context)` 与项目创建选择器复用私有实现，使用安装包标题且不提供新建目录；两者均附着真实调用窗口并沿用失焦保护。选择有效目录后清除原包预览和原生信任，要求重新检查；取消选择保留原输入、预览及信任。不自动安装、执行或刷新插件注册表，不修改第三方桥或协议。
