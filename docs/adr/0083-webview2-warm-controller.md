# ADR 0083：Windows 插件 UI 预热控制器

- 状态：已实现，Windows 实机和耗时验证待完成
- 日期：2026-11-18
- 关联：[ADR 0055](0055-webview2-isolated-plugin-content.md)

## 背景

每次打开 Windows 插件 UI 都要在等待路径中创建独立数据目录、Environment 和 InPrivate Controller，随后才安装宿主策略并导航。提高等待上限只能减少误报。此前在异步创建控制器前后对父窗口子 HWND 求差集，若同一父窗口同时创建其他子控件，枚举结果可能指向其他控件。此前也将其他平台的准备预算从 3 秒一同提高至 20 秒。

## 决策

主窗口运行时就绪后，在 Wails UI 线程启动一个隐藏的空 WebView2 Controller。单个预热槽可以交付已完成或创建中的控制器，且仅向同一 HWND 的请求交付。缺少匹配的槽时按需创建。请求接管后仍须安装该会话的资源拦截、导航和消息策略及启动脚本，等待插件发出 ready。页面就绪直接通知等待方，随后为当前主窗口补充预热槽。

预热实例使用独立目录、独占 Environment 和 InPrivate Profile。接管发生一次，插件关闭、失败或撤销后销毁控制器并尽力删除目录。各次打开继续生成独立虚拟源及会话桥。预热空实例会占用一份额外的 WebView2 资源。主窗口更换 HWND 或宿主退出时回收预热槽，创建超时的空实例也会回收。关闭与原生创建回调交错时，目录清理等到回调完成。异常退出、缺失回调或浏览器延迟释放可能留下目录。

为每个控制器显式创建隐藏的原生子 HWND。控制器以它为父窗口，宿主在布局时将它置于 Shell 之上，并在提交后显示在可信页头下方。拆出继续保留原页面及窗口，隐藏启动继续等到显式显示。

Windows 页面准备上限保留 20 秒，macOS/Linux 恢复 3 秒。协议、SDK、插件清单和发布格式无变化，另外两个插件仓库无需联动。

## 验证

macOS arm64 标准无界面回归通过。Windows amd64/arm64 桌面交叉构建（默认和替代加载器）、桌面及 UI 宿主测试程序交叉编译和静态检查通过。新增无界面用例覆盖预热控制器的窗口匹配、一次性交付、失败/关闭排除及迟到回调，已被现有 Windows CI 测试筛选覆盖，本轮未在 Windows 执行。Linux arm64 在无显示服务器的 GTK3 容器中通过定向竞态回归、静态检查和桌面构建。

Windows 冷启动、预热命中后的就绪耗时、控件层叠、焦点、输入法、隐藏启动、拆出和多 DPI 行为仍待实机验证。
