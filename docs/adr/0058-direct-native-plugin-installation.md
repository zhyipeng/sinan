# ADR 0058：原生插件安装及更新取消二次确认

日期：2026-11-14。状态：已实现，无界面回归验证；真实 UI 未验收。

## 原因与决策

用户明确要求原生插件安装也去掉二次确认。本决策替代 ADR 0050 中保留原生「信任并安装 / 信任并更新」步骤的安排。

插件中心 0.9.0 的商店卡片、详情页、本地目录及 ZIP 安装，对原生候选与纯前端候选统一采用单次操作：用户点击安装或更新，可信组件先检查，发现内容变化后立即应用。可信组件仅在本次已检查候选 `kind=process` 时传递原生信任，点击即为本次候选的运行授权，不再显示原生授权预览、额外按钮或勾选框。

原生进程仍以当前用户权限运行，不构成 OS 沙箱。此次改变属于可信安装界面的授权策略调整，不增加隔离页面能力，不把核心的原生信任检查改为默认允许。CLI 及直接核心调用的信任参数、开发链接的目标路径绑定确认、系统修复及数据清理流程保持原有契约。

## 事务与生命周期

商店 Prepare / Apply 分离、单次票据、当前目录核验、资产摘要与大小、受限解压、源包和已安装包的内容指纹及升级回退继续生效。本地目录和 ZIP 同样使用本次检查返回的指纹，候选或安装基线中途变化会失败，不因移除确认而绕过重新检查。

同内容只提示，不重复安装。检查结束前页面已卸载则取消票据、不继续应用；已发出的安装请求完成后更新命令快照并清理票据。防重复提交及错误反馈沿用原实现。

## 验证

前端类型检查与构建、宿主日常无界面回归沿用原生信任拒绝、指纹变化、单次票据、撤回资产和升级失败回退的检查。人工浏览器回归脚本调整为验证原生升级单次点击后完成；按项目约定不运行真实浏览器或桌面 UI。
