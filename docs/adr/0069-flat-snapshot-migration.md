# ADR 0069：内置插件迁移按扁平发行快照识别

- 日期：2026-11-16
- 状态：已实施；无界面回归通过，未实机验收

## 背景

插件中心在内核中的迁移只接受 `previousManagers` 登记的两个 0.6.0 内容指纹（源码树安装与 manifest/icon 最小包），退役商店同样依赖固定指纹。但 0.7.0 起的发行流程只把 `manifest.json` 与 `icon.svg` 打进内置快照，版本随宿主继续提升（0.8.0、0.9.0～0.9.3），指纹列表从未随之增长。

结果是正常升级被判为异常：安装 v0.2.1（中心 0.9.2）后运行 v0.3.1（0.9.3），启动即提示「插件管理包不是已知内置版本」，插件中心停留旧版本。指纹按安装机器的文件模式计算，macOS 记录的值在 Windows 上不能复现，因此 Windows 上连 0.6.0 的已知包也无法识别；插件中心的迁移测试在 Windows 上因此长期失败。

## 决策

迁移改为以「扁平发行快照」识别宿主拥有的内置声明，不再要求人工扩充指纹列表：

- 已安装包必须是声明式组件，仅有一条 `open` 命令且指向对应可信视图（中心为 `manager`，退役商店为 `store`），没有 `uiViews`、搜索提供者和图片匹配，非开发安装且未被检测为本地改动。
- 包目录内只有 `manifest.json` 与 `icon.svg` 两个普通文件，没有子目录、链接或其他条目。满足条件的包不含用户内容，其行为与界面都由宿主提供：中心可被内置版本替换，退役商店可被清理。
- 设置、私有数据、缓存与使用记录仍在 `.sinan-state`，迁移不读写它们。
- 任何额外文件、子目录、链接、开发安装或本地修改都视为本地变体，保持原样并继续提示，不改用「兼容即可覆盖」。
- 原指纹白名单保留为旧安装（源码树安装）的兼容路径，不再作为唯一依据。

内核为此增加只读 `PackageContents(id)`：返回已安装包的内容指纹、常规文件列表与是否扁平，不解析、不执行插件代码。迁移不再为取得已安装指纹而构造声明探针包。

## 影响与兼容

- 之后提升插件中心版本无需再登记旧指纹；macOS、Windows、Linux 上同一路径可用。
- 代价：若用户手工修改过扁平包内的声明（仍符合中心形态）或图标，内置版本会覆盖这两个文件；这类文件不含用户数据。带任何额外文件的包仍完整保留。
- 提示文案补充分发版处理方式：删除该插件目录后重启，宿主会重新安装内置版本；源码树安装仍可从恢复入口升级。
- 迁移仍不是通用自动升级器，不把相同或更新的版本号当作覆盖授权。

## 验证

新增 0.9.2 发行快照夹具驱动的升级用例、非中心声明的扁平包保留用例、`PackageContents` 的内核用例；`go vet` 与相关包编译通过。Windows 上插件中心迁移套件此前 3 项因平台相关指纹失败，现全部通过。内核其余依赖 POSIX 链接与可执行位夹具的测试仍未迁移，不代表 Windows 完整回归；真实桌面与发行实机验收未执行。
