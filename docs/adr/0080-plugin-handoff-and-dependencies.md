# ADR 0080：插件依赖与带图页面交接

日期：2026-11-17。状态：已按用户确认实现，已随宿主 0.4.0、截图 0.1.0 和 OCR 0.3.0 发布；真实桌面交互未验收。

## 决策

采用已确认的[交接设计](../design/plugin-handoff-and-dependencies.md)：截图后处理调用 OCR 时导出当前编辑结果，在同一所属窗口切换到 OCR 页面并自动识别。成功后释放源页面与编辑历史；准备失败保留源页面。OCR 为可选依赖，不影响截图、标注、导入及输出。

宿主能力为 ui.plugin-handoff.v1，仍使用 API 1 / UI Bridge 2。manifest 增加 dependencies、contributes.entryPoints 和 uiView.dependencies：消费方固定别名到目标 ID、最低插件版本和入口版本，目标显式公开接受图片的普通 HTML 视图命令，视图单独声明可使用的依赖别名。全局 dependencies 本身不授予其他视图调用权；禁止自依赖、重复声明、未知视图引用与硬依赖环。最低插件版本按三段数字比较；首版入口协议版本为 1。硬依赖按可达节点去重解析，最多 128 个可达插件，避免共享依赖图重复展开。

依赖状态由内核查询已安装实例、启用状态、包指纹、版本、公开入口及原生入口文件，不启动目标。只返回调用视图已声明的依赖；执行前、准备和提交时重新验证。硬依赖不足时阻止进程启动、命令执行和视图打开，快照显示 blocked；禁用、升级或卸载引起硬依赖不可用时撤销消费方视图和进程。optional 仅影响相关交接操作。依赖检查不自动安装、更新或启用插件。

插件中心展示依赖的可选/必需状态、版本要求、失败原因及被依赖列表；查看入口可定位已安装插件或商店详情。截图依赖不可用时提供“前往插件中心”：这是固定可信导航目的地，页面不能选择其他可信组件，导航沿用当前窗口并结束截图页面。

## 图片通道与调用

- SDK readDependencies 对应 dependency.status；stageDependencyImage 依次调用 image.upload.start/chunk/finish，openDependency 对应 dependency.open；discardDependencyImage 对应 image.upload.cancel，openDependencyManager 对应 dependency.manage。
- 每个上传绑定源 Session、依赖别名、公开入口和目标包指纹，句柄为 32 字符随机十六进制字符串，只能被同一会话交到同一目标入口，单次消费。
- PNG 最多 4 MiB / 16×1024×1024 像素，沿用 paste.Parse 的完整解码与目标会话快照边界；源编辑器原有 8 MiB / 3200 万像素边界不变，超过交接限制提示先裁剪。
- 每块原始数据至多 36 KiB，严格连续偏移和固定块长（最后一块除外），每图最多 114 块；单请求保持 64 KiB。图片数据帧使用独立每分钟 228 次预算，普通调用仍为 120 次/分钟；每源视图每分钟至多开始两份上传且同一时刻只有一份，原生共用桥仅对结构匹配的数据帧使用独立计数，来源、会话和宿主授权检查不变。
- 上传空闲 15 秒或总计 60 秒后清理，完成句柄保留 30 秒；每秒回收，源会话撤销立即触发清理，单会话图像暂存最多 4 MiB。结合既有 16 会话限制，暂存输入总量有界；PNG 完整解码和目标快照复制还需额外的有界瞬时内存。
- 图片不经过系统剪贴板或共享文件路径。目标取得独立的会话私有 PNG URL，CSP 和资源预算不变；源句柄和调用权限不传递给目标。

dependency.open、dependency.manage、image.upload.finish 和 launch.get 使用 10 秒预算，WebView2 页面等待 12 秒；launch.get 的较长预算容纳目标视图准备和激活门控。现有 window.execute / file.openImage / file.savePNG 保持 125 秒，其余普通调用保持 500ms。

## 准备、提交与失败

目标视图在 PrepareDependencyImage 中创建并挂起业务调用，ready 握手仍可完成；原有 Session.Call 在激活前等待，避免 OCR 提前取得启动图片或创建任务。准备期间核对原生后台初始化，后续真实识别或模型运行错误由 OCR 页面按原有逻辑报告。

提交在内核变更锁下核验源会话、目标实例及指纹，宿主在所属窗口的序号与当前视图仍匹配时替换页面，然后释放目标激活门控。提交成功后才关闭源原生视图；源 ctx 的撤销不影响目标页面新调用的独立 ctx。提交前失败会撤销目标临时视图，原编辑器保持可用。

成功切换不依赖源 JS 收到回执：源会话关闭后，原调用可能按既有桥语义报告已撤销，但页面已被目标替换，不重试交接。窗口任务互斥和单次句柄阻止重复提交。主窗口与拆出窗口复用同一策略。

## 兼容与验证

截图插件仍为未发布的 0.1.0，初始化要求真实 ui.plugin-handoff.v1；OCR 源码升级到未发布 0.3.0，公开 recognize-image 入口，minVersion 为 0.3.0。已发布 OCR 0.2.0 不含公开入口，保留原资产和商店记录。本轮 SDK 快照保留来源提交并记录可重放增量补丁。登记仓库无新资产或协议字段；新版本正式发布时再联动登记真实版本、兼容宿主与资产。

三端共用 Go 依赖检查、图片暂存和原生桥计数；准备/激活通过既有 WKWebView、WebView2、WebKitGTK 承载。仅实现宿主协调的页面交接，没有新增后台跨插件 RPC 或 OS 沙箱。依赖状态是启动前检查，不保证目标模型、动态库和识别任务运行成功。

验证结果见 docs/cross-platform.md；本轮仅无界面测试、构建、原生 OCR 合成图片与 stdio 校验，未运行真实桌面、WebView 或系统剪贴板验收。
