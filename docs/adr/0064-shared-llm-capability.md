# ADR 0064：全局共享 LLM 配置与受限调用能力

日期：2026-11-14。状态：已实现，无界面验证见末尾；真实服务与桌面交互未验收。

## 用户决策与边界

用户要求将 LLM 配置和调用提升为 core 机制，全局创建多套命名配置，插件或不同服务可在每次请求中选择其中一套。保留全局默认及插件默认覆盖。用户明确要求开发阶段丢弃 0.2.0 插件私有 LLM 配置，不实施导入、迁移或旧协议兼容。

设置 UI 保留在 `system.settings` 0.6.0。core 管理配置、凭据、解析配置选择、Chat Completions 传输、任务和取消；翻译等插件仅产生业务提示词与输入，接收文本结果。core 不包含翻译提示词、语言识别或其他业务模板。

## 配置与凭据

- 继续使用 ADR 0063 的 AES-256-GCM 和本地主密钥自动解锁，在同一加密存储的保留宿主命名空间 `$llm` 保存全局配置。插件 manifest ID 不能包含 `$`，普通插件加密读写拒绝保留命名空间；插件数据列表也不枚举宿主记录。
- 共享同一加密存储对象及主密钥初始化互斥，密钥丢失检查覆盖宿主与插件密文，不创建第二套凭据存储或系统钥匙串依赖。20 KiB 总配额和 16 套配置上限继续。
- 设置页面只能读取安全元数据：ID、名称、API 地址、模型和是否已保存 Key；不会读回 Key。编辑时空 Key 保留，显式清除可删除；改地址须重新输入或清除 Key。所有更新按 revision 检查冲突。
- 获授权插件只获得配置 ID 与名称，不获得地址、模型或 Key。调用显式 `profileId` 优先；未指定时按插件覆盖、全局默认解析。插件覆盖仅是默认值，不是配置访问白名单；声明 LLM 的插件可选择任一全局配置，符合用户本轮指令。
- 自定义不同业务服务可在每次 SDK 调用中传入不同 `profileId`，ID 不属于秘密，可由插件自行保存。插件无需维护 Key 或 HTTP 客户端。

## UI Bridge 2 与生命周期

视图显式声明 `permissions: ["llm"]`。新增精确字段请求：

```js
await listLLMConfigurations(); // {profiles:[{id,name}],defaultProfile}
const {id} = await startLLM({profileId,systemPrompt,input});
const task = await pollLLM(id); // {done,text,error}
await cancelLLM(id);
```

对应 `llm.config`、`llm.start`（value）、`llm.poll` / `llm.cancel`（input）。页面不能指定插件身份、路径、地址、模型或 Key；未知内层字段也拒绝。沿用实例、包指纹、ready、来源、撤销、在途、频率及 500 ms 桥调用预算。首版入口为隔离 UI 的窄桥，不宣称已经提供原生后台进程的反向 Host RPC。

HTTP 请求异步运行，总预算 45 秒、HTTP 40 秒；每会话最多 2 个任务、宿主最多 16 个，结果至多保留到 60 秒并在后续调用清理。提示词最多 8 KiB、输入最多 20 KiB，响应预算继续有界。任务绑定具体 UI 会话；其他会话即使属于同一插件也不能读取或取消。关闭/撤销、禁用、卸载、升级及宿主退出取消请求；全局配置修改取消现有任务，后续轮询拒绝旧任务，避免继续使用变更前的凭据。

传输仅接受 HTTPS 或 loopback HTTP，禁账号 URL、查询参数和片段，拒绝全部重定向；Key 仅进入服务端请求头，响应正文和原始网络错误不回显。返回结果若包含正在使用的 Key 则拒绝。不新增工具调用、脚本执行或任意 HTTP 代理。

这不是 OS 沙箱或费用硬限额。原生插件仍具备同账户文件访问能力；能同时读取主密钥与密文的人仍可解密。声明 LLM 意味着可以向用户配置的服务发送输入并产生 API 用量，当前不额外弹授权确认。

## 翻译 0.3.0 与开发期处理

删除翻译的服务地址、模型、Key、配置增删改及 HTTP 调用；原生插件仅保留 `prepare-llm` 生成翻译提示词，页面用共享 SDK 发起请求。页面保留全局配置选择和刷新，空选择跟随默认。免费引擎、复制、语言规则和低内容匹配权重不变。

不读取或迁移 0.2.0 的私有配置，也不保留旧请求结构。旧加密文档作为普通插件数据不参与新功能，可通过原有数据管理清理；不扫描或修改用户其他目录。新插件须配套支持 `llm` 权限与上述桥方法的新宿主。

协议、校验器、Schema、SDK 与生成绑定同步。SDK 来源提交及未并入来源提交的补丁和 SHA-256 按既有规则记录；不把新接口错误归入旧提交。已核对三个仓库，注册目录没有翻译正式发布记录，不新增未上传资产。
