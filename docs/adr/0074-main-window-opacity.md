# ADR 0074：主窗口整体透明度

状态：已实现，未发行；真实桌面显示效果待三端实机验收。

## 决策与原因

按用户确认，透明度作用于整个主窗口，包括文字、可信设置和同窗口隔离插件内容。设置 UI 仍属于 `system.settings`，在通用分类现有内容之后追加原生 range 滑块与百分比。用户看到的是透明度 0%–70%，默认 0%；宿主使用对应不透明度 100%–30%，避免完全不可见。拖动即时应用并自动保存，快速输入合并待处理值、串行提交修订号；鼠标和键盘共用同一设置入口，不新增确认按钮。

内核使用独立保留命名空间 `$window-opacity`，验证整数范围、修订号并持久化。不向插件配置接口开放。损坏记录保留、回退不透明且拒绝覆盖；存储错误不提交新偏好。宿主在原生 UI 线程应用，系统调用失败不保存；保存失败尝试恢复之前透明度，恢复失败明确提示。可信窗口之间通过私有事件同步。主 Shell runtime ready 后恢复已保存透明度，静默启动的隐藏状态不因此改变。

平台适配集中在 `internal/platform`：macOS 使用 NSWindow alphaValue，Windows 使用宿主 HWND 的 WS_EX_LAYERED 和 SetLayeredWindowAttributes，Linux GTK3 使用 gtk_widget_set_opacity，并检查当前 screen 的合成能力。没有合成或没有原生构建能力时明确报告不可用，设置滑块禁用，不用 CSS opacity 模拟桌面穿透。Windows 原有扩展样式保留，新增 layered 样式失败时回退；恢复到 100% 仍可保留 layered 样式，不主动删除可能用于其他机制的扩展位。

## 生命周期和边界

透明度仅作用于当前主窗口。拆出时已应用透明度的旧窗口恢复为不透明，新主窗口在 ready 后恢复设置；恢复原生调用失败通过现有 Shell 错误区提示。原生子视图沿用父窗口合成，第三方 HTML 的来源、权限、资源与 Wails Bridge 隔离不变。旧的独立客体窗口不是主 Shell，保持其既有显示行为。

Linux X11 需要窗口合成器；Wayland 仍由 GTK/合成器能力决定，不能凭编译通过宣称全部桌面环境支持。GTK 与各 WebView 的真实合成、输入、拖动和拆出需实机核验。没有引入新依赖，不更改公开插件协议、SDK、manifest 或商店格式，sinan-official-plugins、sinan-plugin-registry 无需联动。

## 验证

无界面测试覆盖默认值、范围拒绝、旧修订号拒绝、重启恢复、损坏记录不覆盖、存储失败保留；宿主假原生调用验证系统失败不保存以及磁盘失败恢复原生值。平台用例仅以 nil 句柄验证防护，不创建窗口。真实桌面和原生 WebView 验证仅在用户明确要求后执行，具体本轮结果见跨平台文档。
