# ADR 0062：插件后台协调退出时解除主线程等待

日期：2026-11-14。状态：已实现；无界面回归，真实桌面退出未验收。

## 原因

桌面宿主的 Wails `OnShutdown` 在 UI 主线程运行，会取消插件后台协调并等待其结束。后台循环此前在结束前同步注销插件快捷键，Wails 的原生注册表操作又同步等待 UI 主线程，形成相互等待。正常协调中的注册、注销也可能与退出重叠。宿主未退出会继续持有插件目录的 OS 独占锁，下次 `make dev` 在准备插件时报告目录被占用。删除锁文件不能修复进程死锁，也会破坏目录互斥。

## 决策

后台协调继续负责插件启动、配置锁和快捷键贡献同步；仅将原生注册表调用异步投递至主线程，并以运行时 context 取消等待。排队调用执行前再次检查取消状态，退出后不执行迟到操作。协调与配置互斥锁仍在后台，避免主线程等待正在同步调用原生 API 的配置线程。

后台循环退出时不再同步注销快捷键。宿主仍取消并等待后台循环，停止插件进程并关闭目录租约；Wails 在宿主退出回调返回后统一释放全局快捷键。正常禁用、卸载及贡献变化继续通过原有协调释放快捷键。

该变更适用于 macOS、Windows、Linux 的共同桌面生命周期，不增加插件协议、权限或业务能力，不改变进程隔离和目录互斥语义。独立官方插件与注册仓库无须联动。

## 验证边界

无界面竞态测试模拟主线程不能处理队列时，在注册待执行、注销待执行和已注册空闲三种状态取消后台循环；核对循环能结束、关闭管理器后同目录可再次加锁，以及迟到原生调用不会生效。真实终端 Ctrl+C、托盘退出和目标平台窗口行为须另行实机验收，不以模拟调度器测试代替。

本轮 macOS arm64 的 `make test`、新增定向竞态回归与桌面 `go vet` 通过；Windows amd64/arm64 桌面测试程序交叉编译通过，未在 Windows 运行。Linux 本轮未执行原生构建或测试。
