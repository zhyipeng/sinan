# ADR 0040：动态插件复用同一主窗口

日期：2026-11-11。状态：代码已实施，无弹窗检查通过；实际 UI 未验收。

## 用户决策

用户指出仿制页头没有解决体验差异，并明确选择“和插件管理一样，在同一个主窗口里切换页面，焦点、尺寸和返回体验一致”。本决策覆盖 ADR 0022 的逻辑主面板及 ADR 0039 的普通原生页头方案。

## 实现

普通 macOS 路径使用独立 WKWebViewConfiguration 和非持久数据存储，将 WebView 加为当前 Wails NSWindow 的内容子视图。原生内容避开上方 58 DIP，主面板内容区最多 430 DIP，与插件管理使用同一可信 React 页头和 ResizeLauncher；不再创建另一个 NSPanel 来模拟切换。

先准备隐藏页面，等待 ready，按调用窗口序号提交，再定向发送 plugin-view:open。候选失败保留旧页；返回、设置导航、窗口关闭和宿主退出撤销相应会话，取消迟到提交。窗口局部释放不影响其他独立工具窗口。

拆出复用既有 launcher.detach：迁移同一 Wails 窗口角色，保留主 WebView、React 树及原生子视图，创建新的搜索面板；动态内容随原窗口调整大小。原生内容焦点内的拆出和设置快捷键由宿主本地事件监视器转交现有管理操作，不增加页面桥权限。

## 隔离边界与取舍

不复用可信 WKWebView 配置、脚本或完整 Wails Bridge。第三方页面无 DOM 父子关系进入可信页，不注入 React 树；资源仍经过固定 Scheme、CSP、导航拒绝及会话校验，后端仍独立进程。直接适配器保留 256 次请求和 8 MiB 累计资源预算、既有 1 小时寿命、消息与 UI 调用预算，使用响应探测处理 WebKit 内容退出、超时和撤销。

原生 WebView 控制器现在与宿主同进程，不能再声称独立 UI 客体进程的 native 崩溃隔离；也不承诺独占 WebKit WebContent 进程、CPU/内存硬配额或 OS 沙箱。此取舍用于满足真实同窗口交互。独立 helper/管道继续服务探测与历史验证，不作为普通打开路径的必需依赖。

主题和快捷键带修订号同步，候选提交后补取最新偏好，避免准备期间的变更覆盖新值。后端 API 1、UI 桥 2 与原生安装信任保持。

## 验证

`make test`、`go vet ./...`、`make build`、`git diff --check` 通过；新增无窗口检查覆盖内容区不遮挡 58 DIP 页头、主面板内容上限和拆出后扩展、按窗口释放及迟到打开失效，以及资源/请求预算耗尽撤销。最后焦点清理调整通过定向 Go 竞态回归。链接器提示重复 -lobjc，不影响构建。

受项目常态回归约束，本轮未启动桌面、原生 WebView 或浏览器交互；因此实际焦点、原生叠放、输入法和拆出仍需真实 UI 验收，不将无弹窗通过描述为体验已验证。
