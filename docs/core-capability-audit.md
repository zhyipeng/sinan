## 原始已复现缺陷

### P1：派生子进程持有 stderr 时，停止可能无限等待

位置：`internal/plugin/transport/process.go:35`、`:52`、`:175`。

设置 cmd.Stderr = io.Discard 会由 os/exec 建立复制管道及 goroutine；cmd.Wait() 等待复制结束。当前 Stop 只杀直接进程，再无期限等待 exited。插件派生的子进程若继承 stderr，直接进程退出后该管道仍未关闭，Wait / Stop 会继续等待后代释放它。

临时夹具：插件启动持有 stderr 的 sleep 子进程，随后调用 Stop；250 ms 内 Stop 未返回，手动终止该夹具子进程后 Stop 才返回。夹具及进程均已清理。

影响：停止、超时处理、禁用、重载、卸载及宿主退出可能被拖住；持有内核变更锁的生命周期操作还可能阻塞其他管理操作。UI 客体监督也使用 io.Discard 和 cmd.Wait，静态检查显示同类风险，未在该监督器单独复现。

建议：明确直接进程退出和继承管道的等待上限，使用不产生复制 goroutine 的 stderr 丢弃方式或有界等待，设计插件私有后代进程的回收规则。增加后代持有 stderr 的回归，不能只验证直接进程被 Kill。

### P1：受保护的管理插件损坏后，恢复入口无法修复

位置：`internal/kernel/upgrade.go:64`、`:73`，`internal/kernel/manager.go:240`，`apps/desktop/frontend/src/Recovery.tsx:34`。

恢复入口复用普通 ApplyPackage：

- 运行期间已安装文件改变时，升级路径因指纹不一致拒绝恢复，要求先重载或还原。
- 损坏到 manifest 无法加载时，重启会跳过该包；ApplyPackage 转入安装路径，但原目录仍存在，安装再次拒绝。
- 管理插件又受到禁止卸载策略保护，正常入口无法移除损坏目录来重装。

临时夹具安装合法 system.plugin-manager 后损坏其 manifest，分别在当前实例和重启后用原始合法包调用 PreviewPackage / ApplyPackage；两种恢复均被拒绝。未操作日常目录。

建议：独立设计受保护系统插件修复事务，校验固定 ID、可信组件声明和候选包指纹，隔离备份损坏目录后原子替换，并保留失败回滚。无需开放普通禁用或卸载。

### P2：打开新 HTML 页失败，会先丢失原主面板页面

位置：`internal/plugin/uiwindows/controller.go:139`、`:150`、`:156`。

控制器先将 panel 指向新占位实例并撤销旧会话，再准备和启动新页面。如果新页面资源缺失或启动失败，旧会话已不可恢复；清理新占位后也不会恢复旧面板。

临时夹具：保持 A 页会话运行，打开声明合法但缺少入口文件的 B 页。B 打开返回错误，A 同时退出，Main 不再有附着页面。使用无图形的可信管道客体验证控制器行为。

影响：通过管理窗口打开另一 HTML 插件失败，可能造成原页面及未保存输入丢失。范围为开发期 HTML 客体，可信设置/管理页的原窗口拆出不走此路径。

建议：候选页准备、启动成功后再提交主面板替换；失败清理候选并保留旧会话、焦点和输入。为窗口切换增加失败回滚用例。
